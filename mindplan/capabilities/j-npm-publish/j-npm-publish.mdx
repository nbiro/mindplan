# Ship to npm

## Purpose

Domain capability: release `mindplan-mcp` to the public npm registry so maintainers can ship versions safely and consumers can install without cloning from source.

## Overview

Maintainers claim the package once, then publish through a **repeatable publish script** (dry-run → test → publish → verify). Later releases are the same script, triggered automatically when a merge to `main` carries a version npm does not have yet (then tagged `vX.Y.Z`), authenticated with npm Trusted Publishing (OIDC) — no long-lived `NPM_TOKEN`.

Journey state is **computed** from member Interactions. Assembler for automation: `f-github-actions`. Registry boundary: `f-npm-registry`.

Consumer install docs also surface under Adopt MindPlan (`j-agent-onboarding`) via dual membership of `i-npm-publish`.

## Linked Interactions

- `i-npm-publish` — first claim + reusable publish script + consumer install docs
- `i-npm-tag-publish` — GitHub Actions publish on merge to main, wrapping that script via OIDC

## What “healthy” means

- A maintainer can publish from a clean tree with one scripted path
- Merging a version bump to `main` publishes the same artifact without interactive login; a merge without a bump publishes nothing
- README / CONTRIBUTING describe npm install for consumers and merge-to-main release for maintainers
