# MCP runtime (server instructions)

## Purpose

Assembler — the `mindplan-mcp` process entry. Selects CLI vs MCP stdio mode, creates the MCP server and stdio transport, and mounts `if-cli` and `if-mcp-tools`. In MCP mode the server also announces the MindPlan systems dialect as its `instructions`, so any connected host receives it every session without copied files. Does **not** own tool handlers, CLI argument parsing, Interaction domain logic, or the dialect text itself (owned by `f-framework-docs`).

## Shared Substrate Spec

Package: `src/foundations/f-mcp-runtime/`

- `server.ts` — process boot only: mode select (no argv → MCP stdio; else CLI), `McpServer` + `StdioServerTransport` construction, call into `if-mcp-tools` registration and `if-cli` dispatch
- At MCP start, read `templates/agent/playbook.md` from the package root (resolved relative to the compiled module, the same `templates/` that ships in the npm package) and pass its text as the server `instructions` option
- If that file is missing or unreadable, start without `instructions` and write one warning line to stderr; never fail boot over it
- Relies on `src/index.ts` (same Foundation ownership) as the package bin entry that imports this boot module
- May call `ensureDirectories()` from `f-territory-store` at MCP start
- MUST NOT register MCP tools, parse CLI flags, or implement orient/steer/export/init/check handlers

Depends on: `f-territory-store`, `f-framework-docs` (reads the playbook template it owns). Mounts Interfaces that `depends_on` this Foundation: `if-mcp-tools`, `if-cli`.

## Acceptance Criteria

- Process with no argv starts MCP stdio and registers tools via `if-mcp-tools`
- The MCP `initialize` result carries `instructions` equal to the bundled `templates/agent/playbook.md`
- With the template absent, the server still starts, registers tools, and omits `instructions`
- Process with `init` / `view` / `export` / `check` / `help` dispatches via `if-cli`
- `server.ts` imports only Interface packages (and `f-territory-store` for ensureDirectories) — not Interaction handlers
- `npm test` passes with unchanged tool names, schemas, CLI output, and exit codes
