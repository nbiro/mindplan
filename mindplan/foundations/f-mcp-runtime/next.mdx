# MCP stdio runtime

## Purpose

Assembler — the `mindplan-mcp` process: MCP stdio server and CLI shell that registers tools owned by Interactions and boots from thin `src/index.ts`. Resolves the package root (for `templates/`) by walking up to `templates/agent`. Mutate handlers return `changed_files` so agents and humans can see which paths MCP wrote, and an **`anchor`** object (`record` + 1-hop `neighborhood` + optional `next`) so agents can re-anchor without a mandatory second orient. CLI includes `init`, `view`/`export`, and offline `check` (integrity). Registers `force_unship` for mistaken-ship recovery (user-confirmed). CLI `init` installs consumer agent assets including define-entities, plan-project, review-work, and thin code-review skills under `mindplan/agent/`, Cursor-native copies under `.cursor/skills/` (including `mindplan-code-review`) and `.cursor/rules/mindplan.mdc`, and `.cursor/permissions.json`. Supports `init -f` / `--force` so package upgrades can reinstall those assets over existing copies.

Tools speak the Interaction-centric taxonomy: Journey, Interaction, Interface, Foundation, Bug; edges `belongs_to`, `depends_on`, `exposes`, `leads_to`, `affects`.

## Shared Substrate Spec

Package: `src/foundations/f-mcp-runtime/`

- `server.ts` — MCP server registration; CLI (`init`, `view`, `check`, help); wires compiler + store + search + view projection + integrity-check; registers read/write tools; auto-persists `mindplan/map.md` after successful graph mutations
- Zod schemas for node types (Journey|Interaction|Interface|Foundation|Bug) and edge types (belongs_to|depends_on|exposes|leads_to|affects)
- `create_node` scaffolds Interaction/Interface; `link_nodes` validates new shapes; **no `link_dependent`**
- `get_blast_radius` / `orient_for_work`: for Interaction focus, include `reachability` = { exposing Interfaces, containing Journeys, leads_to downstream } alongside reverse-`depends_on` `affected`
- `update_node_status` documents `cancelled`; `force_unship` retained
- **`buildMutationAnchor`** — on successful `create_node`, `link_nodes`, `unlink_nodes`, `open_next`, `discard_next`, `update_node_status`, `force_unship`, `patch_node_territory`, attach `anchor: { record, neighborhood, next }` where `neighborhood` is `findRelatedNodes` focused on the mutated node
- `init` calls install helpers from the project-init package, including:
  - playbook, define-entities / plan-project / review-work / code-review (mindplan/agent), MCP example, integrations, AGENTS.md, `.cursorignore`, `.cursor/permissions.json`
  - `installCursorSkills`, `installCursorRule` — report each Cursor skill path and `mindplan.mdc`
  - Init argv parser accepts `--layout free|prescribed`, `-f`, and `--force`. `-f` / `--force` set `force: true` on all agent-asset installers. `--layout` still independently forces config rewrite.
  - Note: `view`/`export` already uses `-f` as shorthand for `--format`; that is a different command — init's `-f` means force overwrite only under `init`.

Depends on: `f-compiler-rules`, `f-territory-store` (also uses graph-search, view-projection, and integrity-check at runtime).

## Acceptance Criteria

- MCP tools listed in Interaction ownership modules are registered and callable over stdio
- All MCP tools accept the new node and edge enums; `link_dependent` is gone
- Interaction-focused blast radius / orient includes reachability section
- CLI `init` / `view` / `check` / help work against the resolved package root
- CLI `init` installs and reports `review-work` and thin `code-review` skills (mindplan/agent + Cursor `mindplan-code-review`)
- CLI `init` calls `installCursorSkills` and `installCursorRule` and reports their install paths
- CLI `init -f` and `init --force` pass `{ force: true }` to every agent-asset installer; help documents `-f` / `--force`
- Bare `init` (no force) remains skip-if-exists; `--layout` still overwrites config independently of `-f`
- `check` and `check --for-main` exit 0/1 with `Blocked:` lines
- Mutations that succeed refresh the Mermaid map on disk and return `changed_files`
- Successful mutations also return `anchor.record` and `anchor.neighborhood`; `anchor.next` when a next slot is open
- `force_unship` remains registered for mistaken-ship recovery
- Verified via `npm test`
