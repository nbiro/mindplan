# Plan views

Infra — read payloads several read actions share: a node's blast radius (dependents, affected files by owner, tests, rules impact, decisions) and the rules version tag.

## Purpose

Infra — the read payloads more than one read action builds: a node's blast radius (orient's full reply embeds it; `get_blast_radius` returns it) and the rules version tag (orient's rules block and `get_rules`). Split out of `i-orient-plan` so those actions can live apart, since one action may not import another.

## Shared Substrate Spec

Intended files: `src/foundations/f-plan-views/` (`views.ts`)

- `buildBlastRadiusPayload(graph, node, opts)` — reverse-`depends_on` dependents with distance, `capabilities_at_risk`, `affected_files` grouped by owner (`via`: focus, dependent, exposing, importer; `VIA_ORDER`), linked `tests`, `rules_impact`, the focus's decisions and `dependent_decisions` (`blastRadiusDecisions`, `BlastRadiusDecision`, `DependentDecisionsSummary`, `AffectedFileVia`); retired nodes omitted unless `include_retired`
- `rulesVersion(text)` — the short hash that tags a rules text
- `ruleEntriesForReply(entries, { all?, known? })`, `rulesBlock(nodeId, entries, opts)`, `FULL_RULES_DISTANCE` (1) — rule entries as replies return them, each with its `version`: a known version leaves out the text (`unchanged: true`); a source past distance 1 is one line `{ node_id, node_type, via, distance, version, first, count }` (its first top-level rule cut to 100 characters, and how many it has) unless `all`; the block adds `more` naming `include_inherited_rules` when any entry is one line. Pure: the reply depends on the graph only
- `isRetired(node)`

Depends on: `f-domain-model`, `f-territory-store`, `f-compiler-rules`, `f-graph-search`, `f-source-index`.

- **One revision summary (0.18).** `revisionSummaries(node)` is the one `{ change, state, conflicts }` shape, used by orient, write results, and the check.
- **Open revisions (0.18.0).** The blast radius of a node or a change reads `graphUnder(graph, change)` for a change and lists a node's open revisions by change

## Acceptance Criteria

- `orient_for_work` at full depth and `get_blast_radius` return the same blast radius payload as before the split
- `get_rules` and orient's rules entries carry the same version tags
- Verified via `npm test`
