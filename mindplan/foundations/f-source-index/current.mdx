# Source index

## Purpose

Infra — the file-ownership substrate. Owns `mindplan/config.json` shape `{ sources, exclude }`, the file universe, claim expansion from `implements` entries, and a static import lexer/resolver so check and queries can map files ↔ owners without prescribed folders.

## Shared Substrate Spec

Intended files: agent-chosen under this Foundation (e.g. `src/foundations/f-source-index/`)

- **Config** — load/write `{ sources: string[], exclude: string[] }`; missing config → `sources: ["src/**"]`; brownfield may start `[]`; config still containing `implementation_packages` → `Blocked:` pointing at `mindplan-mcp init`. Move former `f-territory-store/config.ts` here.
- **File universe** — git-visible files (tracked + untracked not ignored) matching sources minus exclude; without git, directory walk. Ignore `.gitkeep`.
- **Claim expansion** — expand directory claims ending in `/` to exact files; reject `..` and anything under `mindplan/`.
- **Lexer** — in-house (no runtime `typescript` dep): `import`/`export … from`, side-effect `import "x"`, `import type`, literal `import()` / `require()`; skip non-literal dynamics.
- **Resolver** — relative paths, NodeNext `.js` → `.ts`/`.tsx`, `index.*`, tsconfig `baseUrl`/`paths`; ignore bare packages and targets outside the universe.

Depends on: `f-domain-model` only (no cycle with territory-store).

## Acceptance Criteria

- Config, universe, expand, lexer, and resolver are unit-testable and used by check/steer/orient/init
- `getNodeImplementation` does **not** live here (moves to `i-orient-plan`)
- Verified via `npm test`
