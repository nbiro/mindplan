# Framework documentation

## Purpose

Own MindPlan’s normative documentation so agents stay on the **system** (anti-drift) and run a light **agent development process** with independent review before code reaches the human. Always-on playbook stays a short systems dialect — and now requires **`mindplan-mcp check` before any Reviewer handoff**.

## Shared Substrate Spec

Docs live at repo root and under `templates/agent/` / `mindplan/agent/`. Package folder `src/foundations/f-framework-docs/` is a pointer (no runtime TS).

Surfaces:

- `SPEC.md` — normative taxonomy, compiler gates, Territory Completeness, package ownership
- `AGENTS.md` / `templates/agent/playbook.md` / `mindplan/agent/playbook.md` / `.cursor/rules/mindplan.mdc` — **systems dialect** always-on playbook (byte-identical mirrors)
- `templates/agent/skills/review-work/` (+ mirrors) — subgraph Plan Review + revision-bound Implementation review; parent must prove green `check` before spawn
- `define-entities` / `plan-project` / `code-review` skills — on demand
- `README.md` — product framing
- `templates/agent/integrations/cursor.md` — Cursor Git delivery notes aligned with check-before-review

Canonical edits: `templates/agent/`; mirrors stay in sync.

### Validity before review

Implementing agents MUST run default `mindplan-mcp check` (graph load + packages when `required`) and get exit `0` before:

1. Spawning Plan Review (`draft` → `ready`)
2. Moving to `in-review` / freezing a revision and spawning Implementation review
3. Re-spawning a Reviewer after fixing a Reject

Fix every `Blocked:` first. Optional `--base` / `--for-main` remain local hygiene — not substitutes for default check, and not CI merge gates.

Reviewers SHOULD re-run default `check` and Reject if it fails.

- Cursor integration text no longer treats check as optional Git-only advice for review handoff
