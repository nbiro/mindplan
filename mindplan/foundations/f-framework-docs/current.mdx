# Framework docs

## Purpose

Own MindPlan’s normative documentation: `SPEC.md`, `README.md`, and `templates/`. Document the tool-first channel: short MCP instructions require `get_project`; that tool returns playbook + project description/rules. Seventeen tools. The dialect does **not** prescribe agent code review or a Reviewer gate — quality review is host/project-customizable.

## Shared Substrate Spec

Claims: `SPEC.md`, `README.md`, `templates/`

- SPEC §1.1.1 and abstract: short instructions; `get_project` returns `{ path, description, rules, playbook }`
- SPEC §3.1: `in-review` is a neutral pipeline checkpoint; ship after green check + legal transitions; no Reviewer spawn
- SPEC §8: seventeen tools; `get_project` contract includes playbook
- README: systems-dialect and init blurbs match tool-first; no proportional-review gate
- Playbook: agents receive dialect via `get_project.playbook`; skills on demand are `define-entities` and `plan-project` only
- Agents stub: call `get_project` first; file fallbacks when tools are hidden
- No `review-work` or `code-review` skills under `templates/agent/skills/`

Depends on: `f-domain-model`.

## Acceptance Criteria

- SPEC, README, playbook, stub, and define/plan skills describe the single-tool channel
- Tool count is seventeen everywhere
- Playbook stays one screen, does not paste product text, and does not require a Reviewer
- `in-review` is documented as a neutral checkpoint, not an external-review requirement
