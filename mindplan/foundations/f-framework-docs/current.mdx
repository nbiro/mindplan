# Framework documentation (no prescribed src package layout)

## Purpose

Own MindPlan’s normative documentation: `SPEC.md`, `README.md`, and `templates/` (playbook, stub, skills, integration guides). MindPlan helps an agent think in systems. The always-on artifact is the systems dialect; review and scaffolding load on demand.

This evolution removes leftover prose that still prescribed `src/<type>/<id>/` implementation packages. The shipped contract is: `create_node` scaffolds territory only; owned code is whatever `implements` claims under `sources`/`exclude`.

Keep prior guarantees: slim orient payloads; proportional review with resume-after-Reject; neighbors in place; Atomic Ops as a ship-time ledger; Approve vs ship.

## Shared Substrate Spec

Claims: `SPEC.md`, `README.md`, `templates/`

### No prescribed src package tree

- SPEC §1.1: prescribe only the `mindplan/` territory tree. Implementation is not a dual tree under `src/<type>/<id>/`. Default `sources: ["src/**"]` is coverage config, not a package layout.
- SPEC §6.3: territory-only scaffolds; delete “Also scaffolds `src/...`” from Foundation / Interaction / Interface bullets.
- SPEC §6.3.1: rewrite around `set_implementation_files` / `get_node_implementation` (expanded files; folder claims ending in `/` allowed). No “MUST place code under its package” / “architecture is package roots.”
- README layout section and tool table: match the above; fix `get_node_implementation`, `check`, and add `set_implementation_files`.
- `define-entities`: drop packages on/off and “code under `src/.../<id>/` only”; claim paths with `set_implementation_files`. Keep architectural anti-patterns (fat Interface screens) with illustrative paths only.
- Sync installed skill copies via `init -f`.

Leave alone: this repo’s dogfood `src/interactions/...` tree; illustrative example paths; playbook process rules; integration “follow playbook for all software work” unless a line requires `src/<type>/<id>/`.

Depends on: `f-domain-model`.
