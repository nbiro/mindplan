# Framework documentation

## Purpose

Own MindPlan’s normative documentation so agents stay on the **system** (anti-drift) and run a light **agent development process** with independent review before code reaches the human. Always-on playbook stays a short systems dialect. It requires **`mindplan-mcp check` before any Reviewer handoff**, requires the **parent to spawn the Reviewer** before treating a Review gate as done, and requires **Reviewers to ignore other nodes that are still in progress**. Unfinished work elsewhere in the graph is mergeable — the same decision already made for CI (`check --for-main` is not a merge gate).

## Shared Substrate Spec

Docs live at repo root and under `templates/agent/` / `mindplan/agent/`. Package folder `src/foundations/f-framework-docs/` is a pointer (no runtime TS).

### Validity before review

Implementing agents MUST run default `mindplan-mcp check` (graph load + packages when `required`) and get exit `0` before:

1. Spawning Plan Review (`draft` → `ready`)
2. Moving to `in-review` / freezing a revision and spawning Implementation review
3. Re-spawning a Reviewer after fixing a Reject

Fix every `Blocked:` first. Optional `--base` / `--for-main` remain local hygiene — not substitutes for default check, and not CI merge gates.

Reviewers SHOULD re-run **default** `check` and Reject if **that** fails. They MUST NOT run `check --for-main` as a review gate, and MUST NOT Reject because other nodes are `in-progress`, `in-review`, `draft`, `ready`, or Bug `fixing` / `in-review`. Scope the verdict to the frozen subgraph or revision.

### Spawn before done (parent obligation)

When the build or plan pipeline reaches a Review gate, the **implementing / planning parent** MUST:

1. Enter the gate (`draft` ready for Plan Review, or `in-review` for Implementation review) with green default `check`
2. Freeze membership / revision as required by `review-work`
3. **Spawn** an independent Reviewer subagent (or separate session) that loads `review-work` — do not self-`ready` / self-`ship` / self-`resolved`
4. Own the retry loop (fix Findings → re-enter gate → re-spawn fresh Reviewer, up to the playbook limit) or escalate to the human only after that loop is exhausted

**Done** means: Reviewer returned Approve and advanced status, **or** human escalation after exhausted Rejects. Not done: leaving nodes at `draft`/`in-review` while telling the user the work “wasn’t reviewed,” “needs a Reviewer,” or “handing off for review” without having spawned one.

### In-progress elsewhere is not a Reject

`check --for-main` fails when any Foundation/Interaction/Interface is `in-progress`/`in-review` (including `next`) or any Bug is `fixing`/`in-review`. That mode is optional local hygiene. CI does not require a clean mid-pipeline graph, and Reviewers follow the same rule: other nodes still being built do not block Approve of the frozen membership or revision.
