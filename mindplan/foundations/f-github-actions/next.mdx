# GitHub Actions assembler

## Purpose

Assembler that mounts CI and release jobs for this repository on GitHub Actions. Owns the **CI substrate** and **OIDC permission conventions** for any job that publishes. Does **not** own the release interaction YAML body — that is `i-npm-tag-publish`.

CI verifies that the loaded MindPlan graph and prescribed packages are structurally sound. It does **not** block PRs because work is mid-pipeline or because dirty-src ownership is unfinished. Dirty-src remains an opt-in local `--base` check. There is no `--for-main` flag.

## Ownership split

| Surface | Owner |
|---------|--------|
| `.github/workflows/ci.yml` (integrity CI) | **This Foundation** |
| OIDC / `registry-url` / `id-token: write` conventions for publish jobs | **This Foundation** (applies `f-npm-registry` contract) |
| `.github/workflows/publish.yml` (tag-driven release job steps) | **`i-npm-tag-publish` only** |

Do not duplicate Atomic Ops for writing `publish.yml` on this Foundation.

## Shared Substrate Spec

### CI (integrity only)

- File: `.github/workflows/ci.yml`
- Triggers: push/PR to `main` / `master`
- Matrix: Node 18, 20, 22 — `npm ci` → `npm run build` → `npm test` → `node dist/index.js check`
- `check` is the default integrity mode from `i-check-integrity`: **graph load + package presence/orphans** when `implementation_packages` is `required`. No `--base` (dirty-src). No mid-pipeline flag exists.
- Branch protection SHOULD require this CI job and disallow direct pushes to `main`
- Release automation MUST NOT weaken this integrity gate
- Optional local dirty-src (`check --base`) is documented by `i-check-integrity` / `f-mcp-runtime` — **not** wired into CI

### Conventions for publish jobs (consumed by `i-npm-tag-publish`)

When `i-npm-tag-publish` authors `.github/workflows/publish.yml`, it MUST follow:

- Permissions: `contents: read`, `id-token: write` (per `f-npm-registry`)
- `actions/setup-node` with `registry-url: https://registry.npmjs.org`
- Node: pin one LTS aligned with CI (prefer 22 or 20); no matrix publish
- Invoke the shared publish script from `i-npm-publish` in CI mode (that mode **must** run `npm test` — do not drop tests for a bare `npm publish`)

### Depends on

- `f-npm-registry` — OIDC / Trusted Publishing **contract** (docs); live npm binding is still `i-npm-tag-publish`

### Out of scope

- Authoring or owning `publish.yml` job steps (Interaction `i-npm-tag-publish`)
- Publish script contents (Interaction `i-npm-publish`)
- Changelog automation
- Enforcing “finish the work before merge” via a mid-pipeline check or dirty-src in CI

## Implementation

Package: `src/foundations/f-github-actions/`. CI YAML lives under `.github/workflows/ci.yml` as the deployable surface this Assembler owns. Release YAML is written by `i-npm-tag-publish` under `.github/workflows/publish.yml` (repo-root path is an intentional exception to prescribed packages, same as CI). `.github/workflows/ci.yml` already invokes bare `check`; this evolution does not add a new CI step.

## Acceptance Criteria

- CI runs build, test, and default `node dist/index.js check` (graph + packages) on push/PR
- CI workflow and this territory do not mention `check --for-main`
- CI does **not** invoke `check --base`
- OIDC + `registry-url` conventions for publish jobs remain documented
- Ownership of `publish.yml` remains assigned to `i-npm-tag-publish` only
