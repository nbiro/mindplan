# GitHub Actions

## Purpose

Assembler for CI substrate. Default `check` becomes graph + file ownership (exclusivity, coverage, presence, leftovers, import matrix). Still no dirty-src in CI. Claims `.github/workflows/ci.yml`.

## Ownership split

| Surface | Owner |
|---------|--------|
| `.github/workflows/ci.yml` | **This Foundation** |
| OIDC / registry-url conventions for publish jobs | **This Foundation** |
| `.github/workflows/publish.yml` | **`i-npm-tag-publish` only** |

## Shared Substrate Spec

- File: `.github/workflows/ci.yml` — push/PR to main, plus `workflow_dispatch` so the release `repin` job (`i-npm-tag-publish`) can start CI on its branch (the `pull_request` run of a PR opened with `GITHUB_TOKEN` waits for a maintainer's approval; the dispatched run shows under Actions for the branch, not as PR checks); Node matrix 22.13, 22, and 24 (22.13 is the floor `engines.node` names: the first 22.x with `node:sqlite` unflagged); `npm ci` → build → test → `node dist/index.js check`
- Job `merge-repin` (its behavior is owned by `i-npm-tag-publish`): only on a `workflow_dispatch` run of a `repin/mindplan-mcp-*` branch, after every `test` leg passes, it merges that branch's open repin PR with `GITHUB_TOKEN` (`contents: write`, `pull-requests: write`). The workflow default is `contents: read`, so `test` stays read-only
- `check` is default integrity from `i-check-integrity` (graph + ownership). No `--base` in CI.
- Publish job conventions unchanged (OIDC, registry-url) for `i-npm-tag-publish`

Depends on: `f-npm-registry`.
