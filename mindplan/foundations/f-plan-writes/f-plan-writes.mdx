# Plan writes

Infra — the plumbing every graph-write action shares: the orientation write gate, small write results (changed_files, anchor, readiness reset), stability sync, the persisted map refresh, and dropping a change's planned edges when a write closes it.

## Purpose

Infra — the plumbing every graph-write action shares, so the write actions (status, shape, territory, revision, claims, decisions, brief) can live apart without copying it. Split out of `i-steer-plan`, which held all of them in one module that changed for every write feature.

## Shared Substrate Spec

Intended files: `src/foundations/f-plan-writes/` (`writes.ts`)

- `gateWrite(graph, ids, tool)` — `Blocked: Orientation` unless each node was oriented on with the rules that reach it now (`f-orientation-ledger`); free when the gate is off
- `rulesReachingAfterWrite(id, before)` — after a write that can change the rules reaching a node, return them as a `rules` block and count the node as oriented
- `syncNodes(nodes)`, `territoryPath(node, slot?)`, `changedFiles(paths, withMap?)`, `MAP_REL`, `refreshPersistedMap()` — persist recomputed states and build `changed_files` (the persisted map included)
- `buildMutationAnchor`, `mutationTail(graph, id, verbose)` — the small default write result, the record and 1-hop neighborhood only with `verbose`
- `ReadinessReset`, `readinessFields`, `readinessResult`, `READINESS_NOTE` — the `readiness_reset` fields a contract write on a ready slot returns
- `clearClosedChanges(graph, changes)`, `withChangeCleanup(fn)` — when a write leaves a change with no open revision, drop the planned edges recorded under it (`cleared_planned`), once per call
- `shippedChangeBlocked(node, tool)` — the one `Blocked:` for `change` on a shipped node with no open next (`isShippedWithoutNext`): `"<id>" is shipped with no open next: edit its files in place; it needs no change id (open_next if its contract changes).`

No tool handlers live here; each write action owns its own.

Depends on: `f-domain-model`, `f-territory-store`, `f-compiler-rules`, `f-graph-search`, `f-orientation-ledger`, `f-view-projection`.

## Acceptance Criteria

- Every write action imports its gate, result envelope, and change cleanup from here; no write action imports another
- A write that ships, cancels, discards, or moves the last revision off a change drops that change's planned edges and reports them in `cleared_planned`
- No write result carries `neighbor_of`, `cleared_neighbors`, or `replaced_change`
- Verified via `npm test`

## Decisions

### d-neighbor-cleanup-once-per-write

- Decision: Neighbor labels are cleared by one wrapper (withNeighborCleanup) around every write that can end a change membership, comparing the changes with open revisions before and after the write (carried over from d-neighbor-cleanup-by-before-after on the deprecated i-steer-plan).
- Alternatives:
  - Call the cleanup from each handler path that ends a membership (eight call sites across several actions; a new path that forgets it leaves stale labels)
  - Validate labels when reading neighbors (a neighbor-only change has no revisions by design, so it would lose its neighbors)
- Why: Only an event (a change losing its last revision during a call) tells an orphaned label apart, and one wrapper here covers every write action that can end a membership.
- Consequences: A new write action that can end a membership must run inside withNeighborCleanup.
- Change: hotspot-splits
- Date: 2026-10-31

### d-planned-cleanup-once-per-write

- Decision: Planned edges of a change are dropped by one wrapper (withChangeCleanup) around every write that can end a change's last open revision, comparing the changes with open revisions before and after the write; it no longer touches labels.
- Alternatives:
  - Delete the wrapper with the labels and drop planned edges in each closing path (eight call sites; one forgotten path leaves planned wiring for a closed change)
- Why: Planned edges still close with their change, and the before/after comparison is still the only event that tells a closed change apart.
- Supersedes: d-neighbor-cleanup-once-per-write
- Change: graph-edges-stale-labels
- Date: 2026-10-31
