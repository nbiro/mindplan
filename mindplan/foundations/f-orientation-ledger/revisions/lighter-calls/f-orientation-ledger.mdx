# Orientation ledger

## Purpose

Infra — the record of which nodes had their full context, rules included, reach the agent in this MCP session, and the gate built on it. Orientation now returns summary rows first, so without a gate an agent could write a node without ever seeing its rules; node rules are mandatory, so a write on a node waits until that node was fetched with the rules that apply to it now.

## Shared Substrate Spec

Package: `src/foundations/f-orientation-ledger/`

- `ledger.ts` — in-memory, per process, keyed by the resolved graph root:
  - `enableOrientationGate()` — called by the MCP runtime at start; turns both gates on unless `MINDPLAN_ORIENT_GATE=off`. Off by default, so the CLI (no session) is never gated; `orientationGateEnabled()` reports it
  - `withProposedEdges(graph)` — the graph with each open revision's proposed `belongs_to` / `depends_on` added to its live edges; `reachingRules(graph, id)` — `resolveNodeRules` over it: what orientation shows and what is fingerprinted, so a link into an open revision brings its rules before the revision ships, and orienting once covers writes to any of the node's revisions
  - `rulesFingerprint(graph, nodeId)` — SHA-1 of the node's `reachingRules` entries (`f-graph-search`) as `[node_id, rules]` pairs: it changes when the node's own rules or any inherited rules change, or when an edge brings or drops a source
  - `recordOriented(graph, ids)` — stores each existing id with its current fingerprint
  - `orientationGap(graph, id)` — `unfetched`, `rules_changed`, or null (null while the gate is off)
  - `assertOriented(graph, ids, tool, opts?)` — one `Blocked: Orientation: <tool> acts on …` for every gap at once: a single gap keeps the one-node wording naming `orient_for_work({ node_id: "<id>" })`; several list each id with its reason (not oriented, rules changed) in one message, and name `orient_for_work({ change: "<change>" })` when `opts.change` is set (a walk over one change), else one `orient_for_work({ node_id })` per id; an id not in the graph is skipped so the handler reports that it does not exist
  - `recordProjectRulesServed(version)` — stores the `rules_version` of the project rules (`mindplan/project.md`) that reached the agent in this session: through `get_project`, `get_rules`, `patch_project_rules`, or a reply that carried `project_rules`
  - `projectRulesGap(version)` — `unserved` (nothing served yet), `changed` (the current version differs from the served one), or null (served and current, or the gate is off)
  - `pushProjectRules(brief)` — takes `{ path, rules, rules_version }`; returns `{ project_rules: brief }` when there is a gap and records the version as served, else `{}`. Replies that orient spread it once they are complete (an orient that fails records nothing), so the rules reach an agent the moment they are missing or changed
  - `assertProjectRulesServed(version, tool)` — `Blocked: Rules: <tool> acts before the project rules reached you in this session. Call get_project (or get_rules), with the same root when you passed one, read the rules, then retry.`, or after a change `Blocked: Rules: the project rules changed since they reached you. Call get_rules, read them, then retry.`; a no-op while the gate is off
  - `resetOrientationLedger()` — forget every fetch and every served rules version (tests)

The ledger stores fingerprints and version tags only; callers load the brief and compute its version (`rulesVersion`, `f-plan-views`) and pass them in.

Depends on: `f-graph-search`, `f-domain-model`.

## Graph root per call

The ledger is keyed by the resolved graph root and the node id, so orienting on a node in one worktree never unlocks writes to the same node id in another root.

- **Sent text (0.23.0).** Per project root, the rule source versions whose text a reply carried (`recordRulesSent`, `sentRulesVersions`) and each decision's tag (decision, why, status, superseded_by) last sent (`unsentDecisions(entries, track)` returns the new ones and counts the rest). `tracksSentText(legacy)` is true while the gate is on and config `replies.legacy` is not set. `resetOrientationLedger` clears them
- **Hotspot warnings.** `firstHotspotWarning(nodeId, change)` is true once per node per change per root, so the hotspot text is given once (`i-revise-node`, `i-orient-plan`)

## Acceptance Criteria

- A node fetched with its current rules passes; an unfetched node and a node whose reaching rules changed are Blocked with the fixing call
- A write in a fresh session before `get_project` or `get_rules` is `Blocked: Rules` naming `get_project`; after either call it passes; after `patch_project_rules` from another session the next write is `Blocked: Rules` naming `get_rules`, unless a reply carried `project_rules` first
- `pushProjectRules` returns the brief once per gap and `{}` while the served version is current
- The gates are off in the CLI and with `MINDPLAN_ORIENT_GATE=off`
- A write over three unoriented nodes is Blocked once, naming all three; over one change it names `orient_for_work({ change })`
- Verified via `npm test` (`orient-gate.test.mjs`, `rules-version.test.mjs`)
