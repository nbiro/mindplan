# Orientation ledger

## Purpose

Infra — the record of which nodes had their full context, rules included, reach the agent in this MCP session, and the gate built on it. Orientation now returns summary rows first, so without a gate an agent could write a node without ever seeing its rules; node rules are mandatory, so a write on a node waits until that node was fetched with the rules that apply to it now.

## Shared Substrate Spec

Package: `src/foundations/f-orientation-ledger/`

- `ledger.ts` — in-memory, per process:
  - `enableOrientationGate()` — called by the MCP runtime at start; turns the gate on unless `MINDPLAN_ORIENT_GATE=off`. Off by default, so the CLI (no session) is never gated; `orientationGateEnabled()` reports it
  - `withProposedEdges(graph)` — the graph with each open revision's proposed `belongs_to` / `depends_on` added to its live edges; `reachingRules(graph, id)` — `resolveNodeRules` over it: what orientation shows and what is fingerprinted, so a link into an open next slot brings its rules before the revision ships
  - `rulesFingerprint(graph, nodeId)` — SHA-1 of the node's `reachingRules` entries (`f-graph-search`) as `[node_id, rules]` pairs: it changes when the node's own rules or any inherited rules change, or when an edge brings or drops a source
  - `recordOriented(graph, ids)` — stores each existing id with its current fingerprint
  - `orientationGap(graph, id)` — `unfetched`, `rules_changed`, or null (null while the gate is off)
  - `assertOriented(graph, ids, tool, opts?)` — one `Blocked: Orientation: <tool> acts on …` for every gap at once: a single gap keeps the one-node wording naming `orient_for_work({ node_id: "<id>" })`; several list each id with its reason (not oriented, rules changed) in one message, and name `orient_for_work({ change: "<change>" })` when `opts.change` is set (a walk over one change), else one `orient_for_work({ node_id })` per id; an id not in the graph is skipped so the handler reports that it does not exist
  - `resetOrientationLedger()` — forget every fetch (tests)

Depends on: `f-graph-search`, `f-domain-model`.

## Acceptance Criteria

- A node fetched with its current rules passes; an unfetched node and a node whose reaching rules changed are Blocked with the fixing call
- The gate is off in the CLI and with `MINDPLAN_ORIENT_GATE=off`
- A write over three unoriented nodes is Blocked once, naming all three; over one change it names `orient_for_work({ change })`
- Verified via `npm test` (`orient-gate.test.mjs`)
