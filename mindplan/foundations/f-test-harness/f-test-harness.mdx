# Test harness

## Purpose

Regression suite for MindPlan. Assert MCP `initialize` instructions are the short `get_project` pointer, and that `get_project` returns the bundled playbook with the project brief and the sentence that names the check. The ergonomics suite covers what keeps an agent's session small and honest: the check is reachable and gates shipping, claims report their import fixes, a registry can mount Interfaces, writes return little by default, one section can be patched, a whole open set ships in one call, drift is classified, and stale text warns. The decisions suite covers that recorded reasoning survives and reaches the next agent: records round-trip through every slot move, inherit like rules, supersede without rewriting, and the gate asks for a decision only where one is costly.

## Shared Substrate Spec

Intended files: `src/foundations/f-test-harness/`

- Keep existing ownership / smoke coverage
- Smoke: instructions === short MUST-call constant
- Smoke: `get_project` returns empty description/rules in sandbox, `playbook` equal to `templates/agent/playbook.md`, and a `check` sentence naming `run_check` and `mindplan-mcp check`
- Smoke: init installs `mindplan/project.md`; stub mentions `get_project`
- Smoke: twenty-five tools including `run_check`; a batch status returns one line per node
- `ergonomics.test.mjs` (run by `npm test`): `run_check` equals the CLI output; a registry importing two Interfaces gets two `mounts` fixes, passes once both are mounted, and one missing mount stays Blocked; claiming an unlinked import returns the `link_nodes` call; moving such a node to in-review is Blocked; a default write result is small and `verbose` adds the anchor; section and replace patches (including every Blocked case); orient `depth`; a scoped walk with `dry_run`, validate-first, and one-call ship in dependency order (a draft plan that claims files is not walked); drift classes and scoping; stale-text warnings that never fail the check and skip relative paths
- `check.test.mjs`: drift is scoped to the focus node (a deleted claimed file is found by orienting on its owner)
- `honesty.test.mjs` (run by `npm test`) covers: readiness reset per write and the toggle exemption; `Blocked: Coverage` with probable owner and fix; next-slot import warnings; `skip_review` and the per-step dry run; ambiguous toggles, `all`, `toggled`, notes, and not-applicable reasons passing the completion check; change ids across `open_next`, `scope: "change"`, change blast radius, and change check; glob claims (expansion, exclusivity, path lookup); and the split route-family warning
- `decisions.test.mjs` (run by `npm test`) covers: `record_decision` / `list_decisions` round trip on a live node and on a next slot; promote keeps and discard drops the next slot's decisions; body writes keep the section and a body containing `## Decisions` is Blocked; `orient_for_work` inheritance labeled by source (Interaction from its Journey and Foundation, Bug from the node it affects, no sibling leakage); supersession (status, `superseded_by`, reach and double-supersede Blocks, discard reactivates); each gate trigger (Foundation `open_next`, a new migration file in a git repository (while a first build adopting an existing migration is not gated), blast radius over the setting, a `depends_on` change on a shipped node) warns in `run_check` and is `Blocked: Decision` at in-review, and recording under the change clears it; a body-only Interaction revision and a first build's initial edges are never gated; `get_blast_radius` and `get_node_context` decisions; `export_mindplan_view` decision counts; config defaults (JSON Schema and zod modules are not schema files), validation, and a mistyped setting rejected; a reused change id with an older decision; an id reserved by a dangling `supersedes`; a non-ASCII migration name; compact decisions at depth rules; a deprecated superseder; retired decisions out of the blast radius. The sandbox git ignores the developer's global and system config
- Smoke: twenty-seven tools including `record_decision` and `list_decisions`; smoke and ergonomics record a decision before each Foundation revision reaches in-review, smoke walks a first build that claims `schema.ts` to in-review without one, and smoke checks that Decisions sits before Rules through promote and that legacy `next.mdx` files take entries
