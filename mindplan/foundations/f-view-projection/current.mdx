# View projection

## Purpose

Infra — project the MindPlan graph into Mermaid or DOT for humans, and persist the canonical Mermaid map at `mindplan/map.md` after mutations. Agents must treat MCP export/`find_related_nodes` as authority, not the map file alone.

## Shared Substrate Spec

Package: `src/foundations/f-view-projection/`

- `view.ts` — `prepareViewGraph` (optional focus, hide retired including `cancelled`/`deprecated`); `graphToMermaid` / `graphToDot`; `exportMindPlanView`; `persistMindPlanMap` / `mindPlanMapPath` (`MAP_FILENAME = map.md`)
- Journey subgraphs cluster member Interactions (via `belongs_to`); `belongs_to` edges are **not** drawn as arrows — membership is encoded by clustering only (same as today for Interactions)
- Interactions with multiple `belongs_to` appear in each Journey cluster; Interactions with no Journey sit outside clusters
- Interface nodes render as their own type (no Interaction label)
- Edge rendering: `depends_on` solid; `exposes` solid with `exposes` label; `leads_to` dotted/dashed arrow labeled `leads_to`; `affects` as today
- Bug nodes and deterministic sort preserved

Depends on: `f-domain-model`.

## Acceptance Criteria

- Mermaid and DOT exports render nodes, edges, and states for Journey, Interaction, Interface, Foundation, Bug
- Focused and full-graph views are supported
- `cancelled` and `deprecated` are hidden unless `include_retired`
- Successful graph mutations can refresh `mindplan/map.md`
- `exposes` and `leads_to` are visually distinct; `belongs_to` remains cluster-only
- No Interaction label remains in projections
- Deterministic ordering preserved
- Verified via `npm test` (`view.test.mjs`)
