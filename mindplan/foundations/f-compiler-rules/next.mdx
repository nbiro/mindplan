# Compiler rules (file ownership)

## Purpose

Infra — MindPlan compiler. Keeps existing graph gates. Adds file-ownership gates: entering `in-review` or `ship` requires a non-empty `implements` list on the active slot with every entry present on disk. Import matrix validation (used by check) uses Foundation `role` and a `depends_on` closure that **stops at assemblers**.

## Shared Substrate Spec

Intended files: `src/foundations/f-compiler-rules/`

- Keep Completion Check, Open Checklist While Building, Minimum Territory Shape, Independence, Infrastructure/Behavior First, cancel gates, force_unship, reachability
- New: assert implements non-empty + all entries exist when transitioning to `in-review` or `ship` (Interactions, Interfaces, Foundations)
- New helpers for reachable Foundations (transitive `depends_on`; do not continue past `role: assembler`; while next is open, live and next edges both count)
- Import-matrix predicates consumed by `i-check-integrity` (Interaction / Interface / Foundation / assembler rules as in SPEC)
- Uses `f-source-index` for claim expansion and path presence

Depends on: `f-domain-model`, `f-territory-store`, `f-source-index`.

## Acceptance Criteria

- `in-progress` → `in-review` Blocked when implements empty or missing on disk
- `ship` Blocked under the same implements gate
- Assembler stops transitive Foundation reachability for import allowance
- Existing checklist / ship Completion Check behavior unchanged in spirit
- Verified via `npm test`
