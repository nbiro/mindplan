# Domain model

## Purpose

Infra — shared TypeScript taxonomy for MindPlan nodes, edges, pipeline states, and the optional `next` evolution slot. Every other Foundation and Interaction/Interface imports these types; there is no I/O here.

MindPlan models software as Journeys, Interactions, Interfaces, and Foundations so agents can query architecture without reconstructing it from source each turn.

## Shared Substrate Spec

Package: `src/foundations/f-domain-model/`

- `types.ts` — `NODE_TYPES` = Journey | Interaction | Interface | Foundation | Bug (no Interaction)
- Edge types: `belongs_to` (Interaction → Journey), `depends_on` (Interaction/Interface → Foundation; Foundation → Foundation), `exposes` (Interface → Interaction), `leads_to` (Interaction → Interaction, navigation only), `affects` (Bug → Interaction|Interface|Foundation)
- Execution/production/Bug/Journey state machines and legal transitions (including terminal `cancelled`)
- `MindPlanNode` / `MindPlanEdge` / `MindPlanGraph`; `NextSlot` carries optional `belongs_to`, `depends_on`, `exposes`, `leads_to`
- `PRE_SHIP_STATES` (renamed from `PRE_SHIP_WORKFLOW_STATES`) applies to Interaction and Interface
- `GRAPH_VERSION` stays `1` (breaking change accepted while unreleased)
- Helpers: `isExecutionState`, `isOpenBugState`, `isProductionState`, `isNextPipelineState`, `initialStateForType`

Depends on: none.

## Acceptance Criteria

- No `Interaction` symbol remains in the domain model
- `exposes` and `leads_to` are first-class edge types and optional node/next arrays
- Interaction and Interface share the Foundation build pipeline states
- `GRAPH_VERSION` remains `1`
- Verified via `npm test`
