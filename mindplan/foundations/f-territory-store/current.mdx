# Territory store

## Purpose

Infra — load/persist territory MDX, scaffolds, frontmatter patches, open_next / discard_next / promote_next. Own the project-brief loader (`loadProjectBrief`) that reads `mindplan/project.md` today — the storage seam for description and standing rules. Does **not** own MCP instructions or the playbook body.

## Shared Substrate Spec

Intended files: `src/foundations/f-territory-store/`

- Keep existing store behavior for MDX, edges, implements, role, next slots
- `project.ts` — `loadProjectBrief()`, empty template, `PROJECT_RELATIVE_PATH`
  - Parses `## Description` and `## Rules`
  - `## Rules` is the last section: match through end of file (`$`), not PCRE `\z` (invalid in JavaScript — it was dropping the rules body)
  - Missing or unreadable → empty strings + empty template markdown; never throws
- Callers compose with the playbook elsewhere (`get_project`); this package does not append to instructions

Depends on: `f-domain-model`, `f-source-index`.

## Acceptance Criteria

- `loadProjectBrief` never throws; missing file yields empty description/rules
- When `## Rules` is present, `rules` is the section body (including a last-section file)
- Existing territory load/persist behavior unchanged
