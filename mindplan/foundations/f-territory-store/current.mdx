# Territory filesystem store

## Purpose

Infra — GitOps persistence for the MindPlan territory under `mindplan/`. Discovers the graph from MDX frontmatter, scaffolds entities (and prescribed `src/` packages when configured), and owns `next.mdx` open/promote/discard plus territory body patches. Supports clearing `shipped_at` when recovering a mistaken ship via `force_unship`. Reads `mindplan/config.json` so layout-free projects can opt out of prescribed implementation packages. Create scaffolds stay aligned with the compiler’s **Minimum Territory Shape** gate.

## Shared Substrate Spec

Package: `src/foundations/f-territory-store/`

- `store.ts` — path helpers; frontmatter parse/write; `discoverNodes` / `discoverEdges` / `loadGraph`; scaffold entity + optional implementation package; `readMarkdown` / `writeMarkdown` / `patchFrontmatter` / edge writers; `openNextSlot` / `discardNextSlot` / `promoteNextSlot`; `patchNodeTerritory`; `countUncheckedBoxes`; `getNodeImplementation`; **project config** for `implementation_packages`
- `TYPE_DIRS` / `EDGE_FIELDS` for Interaction-centric taxonomy
- When `implementation_packages` is `off`: no prescribed package dirs
- When `required`: Foundations → `src/foundations/<id>/`, Interactions → `src/interactions/<id>/`, Interfaces → `src/interfaces/<id>/`
- **Body scaffolds (shape-aligned):**
  - Interaction: Purpose / Actor & Trigger / Inputs & Outputs / PRD / AC / Atomic Ops
  - Interface: **Purpose** / Kind / Exposed Interactions / Spec / AC / Atomic Ops
  - Foundation: **Purpose** / Shared Substrate Spec / **Acceptance Criteria** / **Atomic Ops** (replaces Checklist)
  - Bug: Summary / Repro / Expected·Actual / Fix Checklist
- `open_next` / ship-promote / discard_next unchanged in spirit

Depends on: `f-domain-model`.
