# Territory store (implements + role)

## Purpose

Infra — load/persist territory MDX, scaffolds, frontmatter patches, open_next / discard_next / promote_next. Persist server-owned `implements` and Foundation `role`. Stop scaffolding prescribed packages. Move `config.ts` ownership of source globs out to `f-source-index` (this store may re-export or stop owning config).

## Shared Substrate Spec

Intended files: `src/foundations/f-territory-store/`

- `store.ts` — frontmatter rebuild lists in `openNextSlot` / `promoteNextSlot` MUST include `implements` and `role` so they are not dropped
- `create_node` path: do **not** write `src/<type>/<id>/.gitkeep`
- Territory scaffold prose: replace "implement under `src/<type>/<id>/`" with declare files via `set_implementation_files`
- Retired nodes may keep shrinking `implements` lists (enforced by steer/compiler; store must round-trip the field)
- `summarizeGraphNode` stays here
- Config for `sources`/`exclude` lives in `f-source-index`; remove or thin local `config.ts` accordingly

Depends on: `f-domain-model`.

## Acceptance Criteria

- `open_next` copies `implements` and `role`; `ship` promotes them
- New nodes do not get package scaffolds
- Scaffold templates mention `set_implementation_files`, not prescribed folders
- Existing load/patch APIs keep working
- Verified via `npm test`
