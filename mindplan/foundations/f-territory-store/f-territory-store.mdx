# Territory store

## Purpose

Infra — load and persist territory MDX, scaffolds, frontmatter patches, and the evolution slot (`open_next` / `discard_next` / promote). Own the project-brief loader (`loadProjectBrief`) that reads `mindplan/project.md` — the storage seam for description and standing rules. Does **not** own MCP instructions or the playbook body.

## Shared Substrate Spec

Intended files: `src/foundations/f-territory-store/`

Each node folder is `mindplan/<type>/<id>/`. New nodes use `<id>.mdx` for the live record and `<id>.next.mdx` for an open evolution, so review diffs show the node id. Existing `current.mdx` and `next.mdx` stay valid: discover, read, patch, open, discard, and promote keep using the file that is already there. A new evolution follows the live file (`next.mdx` beside `current.mdx`, `<id>.next.mdx` beside `<id>.mdx`). When both names exist for one slot and both are regular files, the id-named file is kept and the legacy file is deleted. The same directory entry is left in place when the names differ only by case, or when the id is `current`. Each deletion is recorded for the caller (`drainRemovedLegacyFiles`). `attachments/` and `next-attachments/` stay directory names.

- `liveMdxFilename(id)` → `<id>.mdx`; `nextMdxFilename(id)` → `<id>.next.mdx`
- `territorySlotFilename` picks the existing file, or the id name when creating one
- `project.ts` — `loadProjectBrief()`, empty template, `PROJECT_RELATIVE_PATH`
  - Parses `## Description` and `## Rules`
  - `## Rules` is the last section: match through end of file (`$`), not PCRE `\z`
  - Missing or unreadable → empty strings + empty template markdown; never throws
- Callers compose with the playbook elsewhere (`get_project`); this package does not append to instructions

Depends on: `f-domain-model`, `f-source-index`.

## Acceptance Criteria

- New nodes are stored as `<id>.mdx` and `<id>.next.mdx`
- A node that still has `current.mdx` / `next.mdx` loads, patches, and evolves in those files
- When both the id name and the legacy name exist for one slot, the legacy file is deleted and the id-named file is kept
- A case-only alias of the same file is not deleted
- Promote and discard still remove a legacy `next.mdx`
- `loadProjectBrief` never throws; missing file yields empty description/rules
- When `## Rules` is present, `rules` is the section body (including a last-section file)
- Graph load, scaffold, edge patches, and promote still round-trip frontmatter and body

## Atomic Ops

- [x] Read and write legacy `current.mdx` and `next.mdx`
- [x] Delete the legacy file when the id-named file is already there
- [x] Leave a same-file pair in place, including a case-only name
- [x] Promote and discard a legacy `next.mdx`
- [x] Green `mindplan-mcp check` and `npm test`
