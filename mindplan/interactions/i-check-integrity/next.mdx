# Integrity check (ownership only)

## Purpose

Offline audit for CI and agents. Default mode loads the graph and enforces file ownership — exclusivity, coverage, presence, leftovers, and the import matrix — and nothing about checkbox state. When a pipeline node has an open next, live presence **skips** implements entries that next has released (via `releasedClaimEntries` from `f-source-index`).

Opt-in `--base` applies lifecycle dirty-src rules using the implements index. Because neighbors now edit their owned files in place without opening `next`, uncommitted changes to files owned by a shipped (`stable` / `unstable`) node with no open next are allowed. Every other working-tree rule is unchanged.

## Actor & Trigger

- **Actor:** CI, agent, or maintainer via CLI (`if-cli`)
- **Trigger:** `mindplan-mcp check` / `node dist/index.js check`

## Execution Logic

1. Load `mindplan/config.json` via `f-source-index` (`sources`/`exclude`; missing → `["src/**"]`; stale `implementation_packages` → Blocked → init).
2. Default check: graph load + exclusivity + coverage + presence + leftovers + import matrix (using compiler reachable-Foundations / role rules). No checklist scan: remove the “Checklist Complete” pass and its use of the compiler’s inherited-checklist helper.
3. **Presence (live):** when the node is `in-review` or production (`stable`/`unstable`), require each live `implements` entry on disk **except** entries returned by `releasedClaimEntries` when `next` is open. Nodes without next keep full live presence.
4. **Presence (next):** required when `next.state === "in-review"`. Ship/in-review gate in `f-compiler-rules` still requires the active slot’s entries to exist.
5. Coverage and exclusivity unchanged. A deleted released file drops out of the universe.
6. `--base <ref>`: dirty-src lifecycle via implements index; fail closed on git errors.
   - Working tree: allowed when the owner (or its open next) is `in-progress`, a Bug affecting it is `fixing` / `in-review`, or — new — the owner is shipped (`stable` / `unstable`) with **no** open next. A shipped owner whose next is open follows the next slot’s state as before. `draft`, `ready`, `in-review`, `cancelled`, and `deprecated` owners still fail.
   - Committed diff: unchanged.

Intended files: `src/interactions/i-check-integrity/`

Depends on: `f-territory-store`, `f-compiler-rules`, `f-mcp-runtime`, `f-source-index`.

## Acceptance Criteria

- A node at `in-progress` with every checkbox checked passes default check
- `--base`: uncommitted edit to a file owned by a `stable` node with no next passes
- `--base`: uncommitted edit to a file owned by a `stable` node whose next is `ready` still fails
- `--base`: uncommitted edit to a file owned by a `ready` node, or by an `in-review` node, still fails
- Stable node with open next that relocates implements: deleted released live entries do not fail presence; entries next still keeps fail when missing
- Next in-review with a missing next entry still fails next presence
- Coverage, exclusivity, leftovers, and import matrix unchanged
- Exit 0/1 with `Blocked:` lines
