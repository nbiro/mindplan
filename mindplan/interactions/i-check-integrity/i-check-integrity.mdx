# Check integrity

## Purpose

Default check Blocks an illegal import with the exact fix. A shipped node has no next file unless a revision is open, so there is no twin to check; a `state: mirror` file left by a release before 0.8.0 only warns, naming `upgrade_project`, which removes it. A graph that needs setup or upgrade fails the check, so CI stops an outdated graph from merging. It prints non-blocking warnings when a node's text no longer matches the repo. The same check is reachable by agents as `run_check`, because a check only the CLI exposes is never run. Also builds a read-only drift report of uncommitted source files and their owners, classified so the actionable files are not buried under expected edits. A later session that only grepped `src/` would miss those owners. The check also warns about every decision-worthy open revision that has no decision yet, from draft on, so the `Blocked: Decision` at `in-review` is never the first the agent hears of it. A change's check covers its neighbors too, the shipped nodes it edits in place, so a feature that touches a shipped helper without revising it is still checked as one piece.

## Actor & Trigger

- **Actor:** human or CI via `mindplan-mcp check`; agents via `run_check`; MCP tools via `f-mcp-runtime` `withDrift`
- **Trigger:** CLI check; `run_check`; `buildDriftReport` from the Assembler envelope used by `if-mcp-tools`

## PRD / Execution Logic

Intended files: `src/interactions/i-check-integrity/`

- Keep ownership checks; there is no mirror-twin check. `legacyMirrorWarnings` adds one `legacy: "<id>" has a leftover mirror twin (<path>); call upgrade_project to remove it.` warning per leftover `state: mirror` next file, and never fails the check
- Import rule: `findAllImportViolations` (`f-compiler-rules`) over the universe plus every file a non-retired node claims (live, next, released), so a claimed file outside the configured `sources` is held to the same import rule the in-review gate applies to it; each failure ends with `Fix: link_nodes({...})` or `not allowed: ...`; a Foundation importing an Interface it mounts is legal
- `runIntegrityCheck` returns `{ ok, failures, warnings, removedLegacyFiles }`; `renderCheckOutput` formats it (`mindplan-mcp check: ok`, or one `Blocked:` line per failure, then `Warning:` lines) for both the CLI and `run_check`
- Warnings never change `ok` or the exit code: a node in review gets every stale-text signal (body names a missing path, a claimed file changed after the body was updated, unticked checkboxes); a shipped node with no open update gets only the path signals (a missing path, and a live `added_claims` entry its body does not name), unless one of its claimed files changed against the default-branch merge base (`defaultBaseRef`; the run's one memoized `dirtyProbe`, matched with `claimCoversPath` as the strict merge gate does): then it gets every signal, because the branch edited it in place. Without git or a base it keeps the path signals and nothing is reported; nodes still being built are skipped
- `runCheckHandler({ base? })` — the `run_check` handler: `{ ok, output, failures, warnings }`
- `buildDriftReport({ nodeIds? })` — uncommitted working tree (`git status --porcelain`), including tracked files deleted from disk. Each path is classified: `unowned`; `owner_idle` (shipped owner with no open update, or a pre-ship owner not in-progress); `claimed_missing` (a claimed path gone from disk); or expected (the owner has an open update claiming the file) — expected is only a count. With `nodeIds` it lists those owners' files and counts the rest (`other_count`); lists are capped. Null when there is nothing to act on or git is unread
- Default `check` still ignores the dirty tree for ownership; editing a shipped node's files in place passes
- `if-mcp-tools` imports this package because it exposes it (`run_check`); the Assembler re-exports the drift envelope
- **Coverage.** An in-universe file (configured `sources` minus `exclude`) that no current or next claim of a non-retired node covers is `Blocked: Coverage: …` with the probable owner (by path) and the exact `set_implementation_files` call, preceded by `open_next` when that owner is shipped with no open evolution and either does not dominate the file's folder or the file is a migration or schema file. A node that claims an exact file in the unclaimed file's folder is the owner the fix names, even when another ranks nearer by path. When no node does, the line leads with the planning duty instead: `A new behavior is a new node: create_node(...), link it, then set_implementation_files(...)`, followed by `If it extends "<owner>" instead: <claim fix>` when an owner exists, so a new feature's first file prompts a node rather than a claim onto the nearest one. One `createCoverageFixContext(root)` per run is passed to every `coverageFix`, so the schema globs are read once and each owner's view of the other claims is expanded once, not once per unclaimed file. A retired node's claim no longer counts as coverage; such a file is reported once, by the leftovers rule, not again as Coverage. The universe is listed once per run and shared by coverage, imports, and route families
- **Next-slot imports.** The import rule runs over every claimant of a file (live, next-slot, released). Violations the check did not scan before (advisory) print as `Warning: imports (next slot): …` for one release, then Block
- **Route families.** Split ownership of one route family is a warning
- **Changes.** `runCheckHandler({ base?, change? })` adds `change: { id, members, failures, warnings }`: each member's active-slot import and ownership violations (Blocked lines that make `ok` false) and its stale-text warnings; a member violation the global import rule already reported is not repeated. Members are the change's open revisions (`changeMembers`), listed with `kind: "revision"`, and its planned sources (below). A change with neither is Blocked (`has no members`)
- **Decisions.** For every open revision (a shipped node with an open next; a pre-ship, non-retired pipeline node at any pre-ship state), `decisionWarnings` (`f-compiler-rules`) adds `Warning: decision: …` lines naming the triggers. One `DecisionContext` (config plus the lazy git probe) serves the whole run. Decision warnings never change `ok`; with `change`, the members' decision warnings are part of the change's warnings
- The dirty-src base is `defaultBaseRef` (`f-source-index`), the same merge base the decision gate uses
- **Version.** When `graphStatus()` (`f-graph-migrations`) is not `current`, the check fails with `Blocked: Version — <warning>` (naming `setup_project`, `upgrade_project`, or the package to upgrade to), before the graph checks run. `MINDPLAN_VERSION_GATE=off` skips it, like the tool gate
- **Linked tests.** `checkPresence` also reports `testPresenceFailures` (`f-compiler-rules`): `Blocked: presence: "<id>" tests entry missing on disk: "<entry>".` for a node in review or shipped. Each in-review revision with no linked tests adds its `untestedWarning` as `Warning: tests: …`; it never changes `ok`. The change check reports both for its members

Depends on: `f-territory-store`, `f-compiler-rules`, `f-mcp-runtime`, `f-source-index`, `f-fan-out`.

- **Merge gate.** `CheckOptions.merge` (`true` or `"strict"`; off by default) adds the rule that the default branch holds only done (`stable` / `unstable`) or still-building (`in-progress`, and the plan states `draft` / `ready`) work. `checkMerge` walks the pipeline nodes and Bugs: a Foundation, Interaction, or Interface whose active slot (the open next while one exists, else live; a mirror twin is not an open next) is `in-review`, and a Bug in `in-review`, are each `Blocked: Merge: …` naming the id, type, state (with `(next)` for a next slot), the change id, and the fix: `update_node_status({ scope: "change", change, new_status: "ship" })` for a node with a change, `update_node_status({ node_id, new_status: "ship" })` without one (a Bug: `"resolved"`), or move it back (`"in-progress"`; a Bug: `"fixing"`) if the work is unfinished. Lines are ordered by change id, then node id, so a change's lines sit together, and the result carries `merge: { level, base?, changes: [{ change, nodes: [{ id, type, state, slot, files? }] }] }` with one group per change (`change: null` for the nodes with none). Cancelled and deprecated nodes pass
- **Stale territory at the merge gate.** With `merge` (`true` or `"strict"`), a shipped (`stable` / `unstable`), non-retired node with no open revision whose live claims cover a path changed against the base (the run's `dirtyProbe`, matched with `claimCoversPath` as strict does) while its live territory file (`mindplan/<folder>/<id>/<id>.mdx`) is not among the changed paths is `Blocked: Merge: "<id>" (<type>, <state>): claimed files changed against <base> but its territory did not: <up to five paths>. Update the node so it matches the code: open_next({ node_id, change }) and ship it when its contract changed, or patch_node_territory({ node_id, ... }) in place when it holds.` When its text still holds, any patch that confirms it clears the Block (the gate cannot judge the text). A node that a Bug changed on the branch (its live file among the changed paths) `affects` is exempt: the Bug describes the fix. Migration and schema files (`schema_files`, matched with `schemaClaimEntries`) do not count: the decision gate covers them. A shipped node's revision still at `draft` or `ready` whose claims (live or its own) cover a changed path is Blocked too (`… but its revision was never started`, naming the ship call or `discard_next`), so `open_next` alone does not clear the rule; an `in-progress` revision merges as incremental work. Its nodes join the `merge` report with `stale: true`. At the default level with no resolvable base or a failed probe the rule is skipped with one `Info: merge: ...` line (strict already Blocks there)
- **Strict merge gate.** With `merge: "strict"`, an `in-progress` active slot whose claims cover a path that changed against the base is also `Blocked: Merge (strict): …` listing up to five changed paths: the work looks finished but was never moved to review. Changed paths are `git diff -z --name-only --no-renames --relative <base>...HEAD` (a committed rename lists its old and new paths, like an uncommitted one) plus the working tree under the project root (`collectDirtySrcPaths`, `git status --porcelain -z --no-renames -- .`, so non-ASCII and space-holding paths come back verbatim and a rename lists both paths; with the root's repository prefix stripped, so a project below the repository top gets project-relative paths), deleted paths included, matched with `claimCoversPath` against the active slot's claims. One memoized probe per run serves dirty-src and strict, so `--merge=strict --base` runs git once and reports a failed probe once. The base is `options.base`, else `defaultBaseRef`; strict outside git or with no resolvable base is `Blocked: Merge (strict): …` with the fix (`--base <ref>`). Strict stays opt-in because it blocks the incremental PRs of a large feature
- `runCheckHandler({ base?, change?, merge? })` passes `merge` through and returns `merge` when the gate ran

- The default check adds `descriptionWarnings` (`f-compiler-rules`) for every node to its warnings; they never change `ok` or the exit code
- **Shape.** The default check adds `shapeWarning` (`f-compiler-rules`) as `Warning: shape: …` for every Foundation, Interaction, or Interface whose active slot is `draft` and every Bug before `in-review`, one line per node naming each missing or stub section and the gate it is required before; it never changes `ok`
- **Planned edges.** With `change`, the check takes its members from `changeMembership` (`f-compiler-rules`) and lists the change's planned sources as members (`kind: "planned"`; no file gates, their files do not change yet) and adds each `plannedEdgeProblems` (`f-compiler-rules`) line as `Blocked: change "<id>": planned edge …` (so `ok` is false), and one `planned edges: "<source>" plans <type> <target>, … under this change (applied when open_next opens it with this change).` info line per source. A change with only planned sources is not `has no members`
- **Attributed presence.** `checkPresence` reports each `attributed` entry missing on disk as `Blocked: presence: "<id>" attributed file missing on disk: "<path>".` once the slot that holds it is in review
- **Planned paths.** `runIntegrityCheck` and `run_check` return `info: string[]` next to `warnings`; `renderCheckOutput` prints them as `Info:` lines after the warnings. With `change`, a member's `planned:` lines from `staleTextWarnings` go to `info`, not `warnings`, so a plan-only change shows one `planned:` line per node and no `stale:` lines for paths it has not built yet. `info` never changes `ok`

**Open–closed signals.** The default check warns `hotspot:` for each shipped node with an open revision whose recent ship rate is an outlier against the graph's median (`hotspots` with the `hotspots` settings), highest rank (rate × fan-in) first, with the refactor its recorded reasons point to (invert, split, or unknown) and its recent change groups; a hotspot nobody is changing is not listed (open_next warns when a change reopens it); a node kept whole by a `keep_whole` decision is skipped. A change check adds the change's additivity summary as an `Info: additivity:` line and `change.additivity`. Neither ever fails the check.

**Fan-out.** The default check warns `fan-out:` for each pre-ship Foundation, Interaction, or Interface whose `depends_on` targets sit in at least `fan_out.warn_at` other unshipped changes (`fanOuts` with `fanOutSettings`, `f-fan-out` and `f-source-index`), one `Warning: fan-out: …` line per node in `fanOuts` order, so a planned node that would have to know every feature of a kind is flagged before it is built; a node kept whole by a `keep_whole` decision is skipped. The settings are loaded once per run. With `change`, a member's `fan-out:` line is also part of the change's warnings. It never changes `ok` or the exit code, and is never Blocked.

**Tool definition.** `run_check` is defined in this action's `tools.ts` (`defineTool`, `f-tool-kit`) and mounted by `if-mcp-tools`.

- **Open revisions (0.18.0).** The check reads every open revision: imports and ownership per change on `graphUnder`, presence and stale text per revision, the merge gate per revision (`slot: "revision"`, its change), and a `conflicts:` warning per revision with unresolved conflicts
- **After merge.** `afterMergeFindings` judges the version stamp of the root it checks (`graphStatus` under `withRoot(root)`), not the process root: a missing stamp, or any state that needs `upgrade_project` (a behind or unreadable stamp, or legacy files the merge brought in), is a failure carrying the version gate's own warning, and a stamp newer than this server (`server-behind`) is one naming the package to install
- **Exclusivity per change.** `checkExclusivity` Blocks a file two nodes claim in one view (live, or one change with its pre-ship members and revisions) and warns about a file claimed from different changes, by revisions or pre-ship members (`ownership: "<file>" is claimed by "<a>" (revision|change "<c>") and "<b>" (…)`)
- **Compact results.** `compactCheckResult` (`compact.ts`) lists the warnings not acknowledged and not seen earlier in this session; `unchanged` counts only the seen warnings it leaves out, so a `nodes`-scoped check, which lists every in-scope warning, reports `unchanged: 0`

## Shared helpers

The check reads revision summaries from `f-plan-views` (`revisionSummaries`), computes the change-cycle search once per run, builds each change's import and ownership verdicts once before filtering them per member, and reads `mindplan/` in one walk for every after-merge finding (`afterMergeFindings`). Warning ids hash the warning text alone and are computed once per run.

## After a merge

The after-merge and compact code read the cache folder name from `f-source-index` instead of repeating it.

`run_check({ after_merge: true })` (CLI `check --after-merge`) validates the graph a git merge produced: git conflict markers in any `mindplan/` file, two nodes created with one id in different folders, a revision file that no longer parses, a decision id held by two files, a tracked `mindplan/map.md`, and a missing or behind `version.json`, each a `Blocked: after-merge: …` line with its fix; a revision whose `base` no longer matches live is a `Warning: after-merge: …` naming `rebase_revision({ node_id, change })` (ship rebases it anyway); the rest of the check runs as usual. `runIntegrityCheck` reads the call's root and never writes `MINDPLAN_ROOT`.

- **One graph memo per check.** `runIntegrityCheck` and `buildDriftReport` run in a graph-memo scope (`withRoot(..., { memoGraph: true })`), so the CLI check's repeated graph loads reuse its first one (`f-graph-cache`); inside `run_check` they keep the tool call's memo

- **Lean drift (`drift.ts`).** `leanDrift()` is what replies carry: `{ count, new_since_last_reply, reminder?, full? }` over every drifting path (unscoped, uncapped `buildDriftReport({ cap: false })`; unowned paths as `class: "unowned"`), listing only entries (path, class, owner) this session was not shown, at most `NEW_DRIFT_SHOWN` (20) per reply with `more_new` counting the rest (only listed entries count as shown); an entry that stopped drifting is forgotten, so its return is new. `fullDrift()` returns `{ count, paths, expected, reminder }` and marks every entry shown. `get_drift` (read, no drift of its own) returns `fullDrift()`
- **Rule checks (`rule-checks.ts`).** The check evaluates every `check:` line (`f-graph-search` parses them): a project rule's over the source universe, a node rule's over the owned files of every active pipeline node the rule reaches, each failure once: `Blocked: Rule: <project|node-id> — "<rule, never cut>" check <json>: <summary>` then up to five `path:line: <text>` lines and `+N more`. Command checks run per config `rule_checks.commands` (`off` default; `local` unless `CI` is set; `always`), else `Info: rule checks: N command check(s) skipped (...)`. A graph without check lines prints nothing new
- **Linked tests (`run-tests.ts`).** `run_check({ run_tests: true, change | nodes })` runs config `tests.command` with `{files}` replaced by the linked tests of the nodes in scope (Blocked without a command, a scope, or any linked test), records each node's result (`f-compiler-rules` auto-items, which close `verify` on a pass), returns `tests: { command, nodes, files, exit_code, passed, without_tests?, output_tail? }`, and on a failure adds `Blocked: Tests: …` and `ok: false`
- **Confirmed territory.** At merge, a shipped node with no open revision whose changed claimed files are all pinned at their current content by `confirm_territory` (`i-confirm-territory`, `f-territory-store` confirmations) passes with `Info: merge: "<id>" confirmed by <by> at <at>: <note>`; otherwise its line names `Unconfirmed:` / `Changed since confirmation:` files and offers `confirm_territory`. `confirmed.json` is not a territory change
- **Answered hotspots.** The hotspot warnings skip a node whose every open revision has a decision under its change

## Acceptance Criteria

- `run_check` output equals the CLI check output
- An illegal import fails the check with its fix; a registry that mounts two Interfaces passes and the same import without the edge is still blocked
- An Interface file claimed outside the configured `sources` that imports an Interaction the Interface does not expose fails the full check, as it fails the move to `in-review`
- A stale body path warns without failing the check
- Drift lists owner_idle, claimed_missing, and unowned files, counts expected edits, and scopes to the focus node
- Clean tree or git failure yields no report (or empty)
- Default check pass/fail behavior otherwise unchanged
- Verified via `npm test`
- A new unclaimed source file fails with `Blocked: Coverage`, its probable owner, and the claim call
- An illegal import in a file claimed only on a next slot warns with `imports (next slot)` and does not fail
- `run_check` with `change` reports the members and fails when a member has an import violation
- `run_check` on this repository's graph reports no new failures
- A Foundation `open_next` revision with no decision prints a `decision:` warning and `ok` stays true; recording a decision under its change removes the warning
- A revision that is not decision-worthy never prints a `decision:` warning
- A graph with no stamp, or a stamp below `MIGRATION_LEVEL`, fails with `Blocked: Version` naming `upgrade_project`; a directory without `mindplan/` fails naming `setup_project`; a current stamp passes
- `run_check` with `change` lists its revisions with `kind: "revision"`; a change with no members is Blocked
- A shipped node with no open next whose claimed file changed against the base gets the full stale-text pass in the plain check (a `stale:` warning for a claimed file newer than its body), and `ok` stays true; outside git it gets only the path signals and nothing reports the missing base
- A shipped node's `added_claims` entry that its body does not name prints a `stale:` warning and `ok` stays true
- The Coverage fix for a file beside a shipped owner's own files, in a folder no other node claims into, has no `open_next`; for a migration or schema file there it does
- A shipped node linking a missing test file fails the check; a draft node linking one does not
- An in-review revision with no tests prints a `tests:` warning and `ok` stays true

- `run_check` stays ok with bad descriptions and lists one `description:` warning per kind
- A leftover `state: mirror` file warns naming `upgrade_project` and the check still passes; a shipped node with no next file passes
- A graph with one `in-review` next slot fails the merge gate with a `Blocked: Merge` line naming the node, its change, and the ship call, and passes the default check
- `draft`, `ready`, `in-progress`, `stable`, and `unstable` nodes pass the merge gate; a Bug in `in-review` fails and a `resolved` one passes
- Several in-review nodes of one change produce one group in `merge.changes`, and their lines are adjacent
- The strict gate fails an `in-progress` node only when a claimed file differs from the base
- The merge gate fails a shipped node whose claimed file changed against the base while its territory file did not, naming `open_next` and `patch_node_territory`; patching its territory on the branch clears it; the default check stays ok in both cases
- An unclaimed file in a folder its probable owner has no file in gets a Coverage line that starts with `create_node` and names the owner's claim fix second; a file beside the owner's own files keeps the claim fix alone
- A scaffolded draft prints one `shape:` warning naming its stub sections and `ok` stays true; once the sections are written it prints none
- `run_check({ change })` on a plan-only change prints one `Info: planned:` line per node naming paths and no `stale:` line for them
- `run_check({ change })` lists a planned source as a `planned` member with an `Info: planned edges:` line, and fails on a planned edge whose target was cancelled
- A shipped node with an open revision shipping well above the graph's median prints one `hotspot:` warning with its diagnosis and recent change groups, and `ok` stays true; an active `keep_whole` decision removes it and superseding that decision brings it back; nodes at one pace print none
- `run_check({ change })` prints one `Info: additivity:` line with the change's summary and carries `change.additivity`
- A pre-ship node depending on nodes in 3 other unshipped changes prints one `Warning: fan-out:` line naming them and `ok` stays true; 2 changes print none; `keep_whole: true` on the node removes it; `fan_out.warn_at: 2` in `mindplan/config.json` makes 2 changes warn

_None._

## Open human items

The check lists every unticked `review` and `deploy` checklist item in one compact `Info: waiting on people: …` block (`<node>[ (revision <change>)]: <id or text> (<kind>)`, grouped by node); it never changes `ok`.

## Compact output

- `run_check` over MCP is compact by default (`compact: true`): `{ ok, counts: { <category>: n }, failures, warnings, info, acknowledged, unchanged }` where `warnings` lists only warnings this MCP session has not already returned for this root (kept in memory per server process; `compact: false` records nothing) and not acknowledged, except that with `nodes` every warning on those nodes is listed; each line appears once (no separate `output` copy). `compact: false` returns today's full shape (`output`, `failures`, `warnings`, `info`). The CLI prints the full output.
- `nodes: [...]` limits warnings and the per-node checks to those nodes (graph-wide failures still count); `change` already scopes to a change.
- Every warning carries a stable id (`w-` + 10 hex of sha1 over category, node, and the warning text). `acknowledge_warning({ id })` (or `ids`) stores the id in the acks file of the root's git-ignored cache folder (one per checkout); an acknowledged warning is left out and counted under `acknowledged` until its text changes (a new text is a new id).
