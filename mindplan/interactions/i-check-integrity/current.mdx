# Integrity check (file ownership)

## Purpose

Offline audit for CI and agents. Default mode loads the graph and enforces file ownership: exclusivity, coverage, presence, leftovers, and the import matrix. Opt-in `--base` applies lifecycle dirty-src rules using the implements index.

## Actor & Trigger

- **Actor:** CI, agent, or maintainer via CLI (`if-cli`)
- **Trigger:** `mindplan-mcp check` / `node dist/index.js check`

## Execution Logic

1. Load `mindplan/config.json` via `f-source-index` (`sources`/`exclude`; missing → `["src/**"]`; stale `implementation_packages` → Blocked → init).
2. Default check: graph load + exclusivity + coverage + presence + leftovers + import matrix (using compiler reachable-Foundations / role rules).
3. `--base <ref>`: same lifecycle dirty-src rules as before, but owners come from the implements index; changed file with no owner fails. Fail closed on git errors.
4. Remove package presence, orphan-dir, and `.gitkeep` scaffold exemption paths.

Intended files: `src/interactions/i-check-integrity/`

Depends on: `f-territory-store`, `f-compiler-rules`, `f-mcp-runtime`, `f-source-index`.

## Acceptance Criteria

- Default check fails on double-owned, unowned universe, missing presence on in-review/shipped, retired leftovers, and illegal imports
- Default check does not invent mid-pipeline bans
- `--base` uses implements ownership
- Exit 0/1 with `Blocked:` lines
