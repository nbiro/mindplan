# Integrity check CLI

## Purpose

Offline audit that CI and agents run without starting MCP stdio. Default mode validates that the territory **graph loads** and (when packages are `required`) prescribed packages match the graph — structural constraints only. Dirty-src ownership and mid-pipeline bans are **opt-in** local hygiene; they must not be required to merge open work.

## Actor & Trigger

- **Actor:** CI job, agent, or maintainer at the CLI
- **Trigger:** `mindplan-mcp check` / `node dist/index.js check` (wired by `f-mcp-runtime`); this repo’s CI invokes the default mode after build

## Execution Logic

1. Load `mindplan/config.json` (missing → `implementation_packages: "required"`).
2. `mindplan-mcp check` (default) loads the territory graph.
   - When `required`: verify every non-retired Foundation/Interaction/Interface has its prescribed package; reject orphan `src/` package dirs. **Do not** run dirty-src.
   - When `off`: skip package presence and orphans. Still validate the graph loads.
3. `mindplan-mcp check --base <ref>` (opt-in) additionally enforces dirty-src ownership vs that git base: uncommitted `src/` needs `in-progress` (or next in-progress / Bug fixing/in-review); committed diffs vs base allow review/shipped/cancelled/deprecated, but when `next.mdx` is open only next `in-progress`/`in-review` counts. Exception: `src/{foundations,interactions,interfaces}/<id>/.gitkeep` scaffolds from `create_node` are allowed while the owner (or open `next`) is `draft`/`ready`. Explicit `--base` fails closed on git errors. Requires `required` packages; skipped when `off`.
4. `mindplan-mcp check --for-main` (opt-in local hygiene) runs graph (+ package checks only when `required`) and fails if any Foundation/Interaction/Interface is `in-progress`/`in-review` (including `next`), or any Bug is `fixing`/`in-review`. Skips dirty-src. **Not** wired into CI — unfinished work must remain mergeable.
5. Wired from `f-mcp-runtime` CLI (`node dist/index.js check`); this repo’s CI builds from source and stays on `required`.

Package: `src/interactions/i-check-integrity/`

- `check.ts` — `runIntegrityCheck`, config-aware package/orphan/opt-in dirty-src/`--for-main` validators

## Acceptance Criteria

- Default check with `required`: fails on orphan/missing packages; **passes** with dirty unowned `src/` (dirty not run)
- Default check with `off`: missing packages and dirty `src/` do not fail
- `--base <ref>` with `required`: same dirty-src ownership rules as before (scaffold exemption, fail-closed bad ref)
- `--for-main` fails on mid-pipeline states and passes on draft/ready/stable/cancelled/deprecated graphs; remains available but is not a CI merge gate
- Exit code 0/1 with `Blocked:` lines for CI
