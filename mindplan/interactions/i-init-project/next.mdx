# Init project

## Purpose

Scaffold a consumer repo for MindPlan: territory layout, project config, agent playbook/skills, Cursor copies, integrations, and AGENTS.md. Support `init -f` / `--force` to reinstall templates after package upgrades.

## Actor & Trigger

- **Actor:** maintainer or agent via CLI (`if-cli`)
- **Trigger:** `mindplan-mcp init` (optional `--layout`, `-f` / `--force`)

## Execution Logic

Package: `src/interactions/i-init-project/`

- `init.ts` — existing `initProject` + install helpers (playbook, skills, Cursor copies, config, etc.)
- `resolvePackageRoot(moduleUrl)` — walk up to find `templates/agent` (moved from `f-mcp-runtime`)
- `runInit({ force, layout?, forceLayout? })` — runs every installer and returns a structured report for the CLI to print
- Layout/config writing stays in install helpers; CLI argv parsing stays in `if-cli`

Depends on: `f-territory-store`. Belongs to: `j-agent-onboarding`. Leads to: `i-orient-plan`.

## Acceptance Criteria

- `runInit` installs the same assets as today's CLI init
- `-f` / `--force` overwrite agent assets; `--layout` still controls config rewrite independently
- Package-root resolution works from nested `dist/` paths
- `npm test` / smoke init cases pass
