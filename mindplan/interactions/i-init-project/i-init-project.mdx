# Init project

## Purpose

Init installs the playbook, project brief, and host copies for the chosen host (Cursor, Claude Code, or both). It ignores the `mindplan/` tree in Cursor (`.cursorignore` → `mindplan/**`) and removes the `state: mirror` twins earlier releases kept beside shipped nodes.

## Actor & Trigger

- **Actor:** human via CLI
- **Trigger:** `mindplan-mcp init [--host cursor|claude|all]`

## PRD / Execution Logic

Intended files: `src/interactions/i-init-project/`

- `runInit` takes `hosts` (default `["cursor"]`) and installs only the chosen host copies
- Cursor host: `.cursorignore`, `.cursor/skills/`, `.cursor/rules/mindplan.mdc`, `.cursor/permissions.json`
- Every host: `installSearchCacheIgnore()` adds `.mindplan-cache/` (the derived search cache, `f-search-index`) to the repo's `.gitignore` under a one-line comment, creating the file when missing and keeping its line endings; an existing entry (`.mindplan-cache`, with or without a leading or trailing `/`) is left alone. The report carries `searchCacheIgnore` (`installed`, `path`)
- Claude Code host: `CLAUDE.md` containing `@AGENTS.md`, and `.claude/skills/mindplan-*`; an existing `CLAUDE.md` is kept unless `--force`
- The report carries `cursor` and `claude` groups that are present only when selected
- **Merge-gate workflow.** `runInit` takes `ci` (`"github"`, or absent: nothing is installed). `installMergeGateWorkflow` copies `templates/ci/github/mindplan-merge-gate.yml` to `mindplan-merge-gate.yml` in `.github/workflows/` at the repository top (`repoTop`, `f-source-index`; outside git, under the project root), where GitHub reads workflows, replacing `{{MINDPLAN_DIR}}` with the project root's path below the top (`.` at the top) for `defaults.run.working-directory`, and `{{MINDPLAN_VERSION}}` with the running package's `major.minor`; the reported path is relative to the project root, so `npx -y mindplan-mcp@<major.minor> check --merge` runs a release that has the flag. It runs on `pull_request` and its job runs only when the PR targets the repository's default branch (`github.base_ref == github.event.repository.default_branch`). The workflow is repo-owned: an existing file is kept unless `--force`. The report carries `ci` (`installed`, `path`) only when requested
- **Shipped ledgers.** `dropShippedAtomicOps()` runs after the installers: for every shipped Foundation, Interaction, or Interface (it has `shipped_at` and is not cancelled) it removes the live file's Atomic Ops with `stripLiveAtomicOps` (`f-territory-store`), so a project upgraded from a release that kept shipped ledgers shows each node's current state. An open next file keeps its own list. The report carries `atomicOpsDropped` (node ids) and the CLI prints one line with their count. A graph that cannot load is skipped, like the backfill
- **Leftover twins.** `removeLegacyMirrorTwins()` runs after `dropShippedAtomicOps`: it deletes every `state: mirror` next file (and its `next-attachments/`, when that holds nothing but `.gitkeep`) through `removeLegacyMirror` (`f-territory-store`). An open revision's next file is never touched. The report carries `mirrorTwinsRemoved` (repo-relative paths) and `mirrorTwinSkips` (`{ node_id, reason }` for a file it could not delete); the CLI prints the count and each skip
- Graph-load failures during these passes are skipped (incomplete migration fixtures)
- **Version stamp.** Init reads `mindplan/version.json` before installing. Package-owned files (the playbook, both skills, `mcp.json.example`, `integrations/`, the host skill copies, and `.cursor/rules/mindplan.mdc`) are rewritten when the stamp is missing, unreadable, or older than the package, as if `--force` were passed for those files only. Repo-owned files (`AGENTS.md`, `CLAUDE.md`, `.cursorignore`, `.cursor/permissions.json`, `mindplan/project.md`) still change only with `--force` (the brief never).
- A stamp newer than the package is `Blocked:` before any write (upgrade `mindplan-mcp`, or pass `--force` to downgrade the tree).
- After the installers and migrations succeed, init writes the stamp with the running package version and graph format. The report carries `version: { from, to, refreshed }` (`from` is null when there was no stamp).

Depends on: `f-territory-store`, `f-source-index`.

**Revision backfill from git.** (History and split inference: `shipHistory`, `inferredSplits`, `replayChurn` in f-compiler-rules; a split is inferred only when claimed files move from the node to the new Foundation in that ship.) For each shipped Foundation, Interaction, and Interface whose live file has no `revisions`, init reads the file's git history (`fileShipHistory`, f-source-index: one `git log --follow` plus one `git cat-file --batch` read): each distinct `shipped_at` value is a ship (read with the store's `parseFrontmatter` from `fileHistory`, f-source-index, at the first commit that has it). A node file git has never seen at its path (one this init just renamed) is skipped, so a later init counts its real history once the rename is committed. It writes `revisions` as the number of ships (at least 1). A ship whose `depends_on` gained nodes that first shipped after the node's previous ship and no later than this one is a split: the last such ship sets `split_at`, and the nodes gained are added to `split_into`. Outside git, or for a file git has never seen, it writes `revisions: 1`. It also writes `churn`, replaying the ships' `shipped_at` values through the same decay (reset to 0 at a split). Nodes that already carry both `revisions` and `churn` are left alone, so a second init changes nothing. The report lists `revisionsBackfilled` (node ids) and `splitsFound` (node id → parts).

## Acceptance Criteria

- Init deletes every `state: mirror` next file and reports the paths; a rerun deletes nothing; an open revision's next file stays
- Init on a project whose shipped nodes still carry ticked Atomic Ops removes those sections from the live files, reports the node ids, leaves an open next file's list alone, and a rerun drops nothing
- `--host claude` installs `CLAUDE.md` and `.claude/skills/` and no Cursor files
- `--host all` installs both hosts; the default still installs Cursor only
- Host ignore covers the whole mindplan tree for Cursor
- Init stamps `mindplan/version.json`; a rerun with an older stamp refreshes package-owned files and leaves repo-owned files alone
- Init refuses a stamp newer than the package unless `--force`
- Init adds `.mindplan-cache/` to `.gitignore` once; a rerun does not add it again
- `init --ci github` writes `mindplan-merge-gate.yml` under the repository top's `.github/workflows/` (running in the project root when it sits below the top), running `check --merge` at the package's minor version; a plain init writes no workflow; a rerun keeps an edited workflow unless `--force`
- Verified via `npm test`

- In a git sandbox where a node shipped three times and its last ship added `depends_on` to two nodes first shipped in that commit, init writes `revisions: 3`, `split_at: 3`, and both ids in `split_into`; a second init writes nothing; outside git it writes `revisions: 1`

- In a git sandbox where a Foundation's ship adds `depends_on` on a new Foundation but keeps every claim, init records no split; where the ship moves a claimed folder to the new Foundation, it records the split
