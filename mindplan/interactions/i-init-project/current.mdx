# Init project

## Purpose

Scaffold consumer repos and migrate brownfield configs. Install agent assets and `mindplan/project.md` (description + rules only) when missing. The AGENTS.md / Cursor stub requires `get_project` before answering or writing code.

## Actor & Trigger

- **Actor:** maintainer or agent via CLI (`if-cli`)
- **Trigger:** `mindplan-mcp init` (`-f` / `--force` only; no `--layout`)

## Execution Logic

Intended files: `src/interactions/i-init-project/`

- Keep existing installers (playbook, skills, stub, migrations)
- `installProjectBrief` — write empty `mindplan/project.md` when absent; **never** overwrite
- `runInit` report includes `projectBrief`
- Stub (owned by `f-framework-docs`) requires `get_project`; file fallbacks when tools are hidden

Depends on: `f-territory-store`, `f-source-index`.

## Acceptance Criteria

- Fresh `init` writes `mindplan/project.md` when missing
- `init -f` leaves an existing project brief untouched
- Stub mentions `get_project` and the file fallbacks
- Verified via `npm test`

## Atomic Ops

- [x] Add `installProjectBrief` and report it from `runInit`
- [x] Build and run tests (`npm test`)
- [x] Verified by Reviewer against the contract
