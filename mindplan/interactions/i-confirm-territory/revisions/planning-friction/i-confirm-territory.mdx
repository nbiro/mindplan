# Confirm a node's territory

## Purpose

The merge gate Blocks a shipped node whose claimed files changed while its text did not. Often the text still holds (a removed npm script, a bumped constant), and the agent had to invent a prose patch to pass. `confirm_territory` records that the text still holds for those files at their current content; changing a file again takes the confirmation back, so real stale text still Blocks.

## Actor & Trigger

- **Actor:** agent
- **Trigger:** the `confirm_territory` MCP tool (write). It passes the orientation gate through `gateWriteOrOrient` (`f-plan-writes`): on a node never oriented on in this session it orients the node itself and returns `oriented: true` with its rules, because a confirmation changes no text, edge, or state that the rules could have shaped; a node whose rules changed still Blocks

## PRD / Execution Logic

Intended files: `src/interactions/i-confirm-territory/` (`handlers.ts`, `tools.ts`); the confirmation file is read and written by `f-territory-store` (`confirmations.ts`).

- `confirm_territory({ node_id, note, files? })` on a shipped (`stable` / `unstable`) Foundation, Interaction, or Interface with no open revision. `files` default: its claimed files changed against the default-branch merge base, counted as the merge gate counts them; each given file must be claimed by the node.
- Appends `{ by, at, note, files: { <path>: <hash> } }` to `confirmed.json` in the node folder (newest last, at most 10 kept). `by` is `git config user.name`, else `USER` / `USERNAME`, else `agent`; the hash is SHA-256 of the file with CRLF normalized to LF, or `deleted`. The file never shapes the node record and changes no state, readiness, text, or edge.
- Returns `{ node_id, confirmed: { by, at, note, files }, changed_files }`.
- Blocked: unknown node; a Capability or Bug; a retired or never-shipped node; an open revision (it ships its own text); an empty `note`; a file the node does not claim (names its owner, or no node); no git base when `files` is omitted; nothing changed against the base.
- **Merge gate (`i-check-integrity`).** A shipped node whose changed claimed files are all pinned at their current content (the newest confirmation naming each file decides) passes with `Info: merge: "<id>" confirmed by <by> at <at>: <note>`; otherwise its line names `Unconfirmed:` and `Changed since confirmation:` files and offers `confirm_territory` beside `open_next` + ship and `patch_node_territory`. `confirmed.json` changing is not a territory change.

## Acceptance Criteria

- Confirm, then `check --merge` passes the node; edit a confirmed file again and it Blocks with "changed since confirmation"
- A partial confirmation still Blocks the unconfirmed file
- After a confirmation the plain check no longer warns `stale:` about the confirmed files changing after the body (`i-check-integrity` reads the same confirmations)
- `confirm_territory` on a node not yet oriented on in this session succeeds and returns `oriented: true` with its rules
- LF and CRLF content hash the same; the default check never reports `confirmed.json`
- Verified by `confirm-territory.test.mjs` and `merge-gate.test.mjs`
