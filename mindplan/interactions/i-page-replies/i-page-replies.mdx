# Page a long reply

## Purpose

Every MCP reply stays under a size budget (`replies.budget_bytes`, default 8 KB), so one call never floods the agent's context. A list cut to fit is kept for the session under a cursor; `next_page` returns the rest when the agent needs it.

## Actor & Trigger

- **Actor:** agent
- **Trigger:** a reply carrying `truncated: [{ path, shown, total, cursor }]`; the `next_page` MCP tool (read)

## PRD / Execution Logic

Intended files: `src/interactions/i-page-replies/` (`handlers.ts`, `tools.ts`); the budget and the cursor store are `f-tool-kit`'s (`pages.ts`).

- `next_page({ cursor })` → `{ path, from, items, total, next_cursor? }`: the next items of that list that fit the budget (at least one). Reading a cursor does not consume it, so the call is idempotent; the store keeps the latest 64 cursors for the session.
- Blocked: an unknown or expired cursor (repeat the original call).
- Mounted by `if-mcp-tools` with `drift: false` and `budget: false` (it sizes itself).

## Acceptance Criteria

- A reply over the budget carries `truncated` with a cursor; walking `next_cursor` returns every remaining item once
- An unknown cursor is Blocked
- Verified by `lighter-calls.test.mjs` and `ergonomics.test.mjs`
