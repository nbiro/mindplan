# Record a decision

## Purpose

Records why a design was chosen over its alternatives, on the node it shapes, so the next agent reads the reasoning before reshaping it. Records are never rewritten: a changed decision is a new record that supersedes the old one. A `keep_whole` decision also tells hotspot detection the node stays one node on purpose.

## Actor & Trigger

Agent calls `record_decision` when it chooses between viable designs, or when the decision gate or an `open_next` decision prompt asks for one.

## PRD / Execution Logic

Intended files: `src/interactions/i-record-decision/` (`handlers.ts`, `tools.ts`).

- `record_decision({ node_id, decision, alternatives, why, consequences?, supersedes?, change?, id?, keep_whole? })` appends one entry (`appendDecision`) to the node's active slot: the open next file while a shipped node evolves, else the live file. `decision`, `why`, and `consequences` are trimmed to one line; `alternatives` needs at least one non-empty item
- `id` defaults to one generated from the decision's first words; a given id must be `d-` plus a slug and unused anywhere in the graph (an id a `supersedes` still names is taken)
- `change` defaults to the node's active change, or a neighbor's label; on a shipped node with no open next an explicit `change` also labels it a neighbor (`labelNeighbor`, `f-plan-writes`). `date` is today in UTC
- `supersedes` must name an active decision held by the node or by a node it inherits decisions from (its Journeys, its transitive Foundations); the old entry stays as written and becomes `superseded`
- `keep_whole: true` writes `- Keep whole: true` on the record
- Blocked: unknown node; inactive node; a Bug (record the decision on the node the fix shapes); empty decision or why; no alternative; a bad or taken id; an invalid change id; a `supersedes` that is unknown, already superseded, or out of reach
- Output: `{ node_id, slot, decision, supersedes?, changed_files, state, next_state }`; never resets readiness and does not rewrite `mindplan/map.md`
- Orientation gate on `node_id`

Depends on: `f-plan-writes`, `f-compiler-rules`, `f-territory-store`, `f-graph-search`, `f-domain-model`, `f-tool-kit`.

## Acceptance Criteria

- `record_decision` writes a structured entry that `list_decisions` returns; on a node with an open evolution it lands in the next file only
- Superseding marks the old decision superseded; superseding an unknown, already-superseded, or out-of-reach decision is Blocked, and so is a taken id
- `record_decision` on a `ready` revision does not reset readiness
- `record_decision` on a labeled neighbor without `change` records the decision under the label
- `keep_whole: true` is written and read back, and the node stops being a hotspot until the decision is superseded
- A Bug is refused with the nodes it affects named
- Verified via `npm test`

## Decisions

### d-record-refuses-bugs

- Decision: record_decision refuses Bugs; the decision goes on the node the fix shapes (carried over from d-bugs-hold-no-decisions on the deprecated i-steer-plan).
- Alternatives:
  - Allow decisions on Bugs (nothing inherits from a Bug, so the reasoning would never reach the next agent)
- Why: Decisions are only useful where inheritance delivers them.
- Change: hotspot-splits
- Date: 2026-10-31

### d-record-optional-id

- Decision: record_decision takes an optional id and otherwise generates one from the decision's first words (carried over from d-optional-decision-id on the deprecated i-steer-plan).
- Alternatives:
  - Require an id (more friction for every record)
  - Always generate (no stable, readable names like d-capacity-on-booking)
- Why: Readable ids matter for supersedes, but a missing id should not block recording the reason.
- Change: hotspot-splits
- Date: 2026-10-31
