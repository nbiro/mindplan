# See the map

## Purpose

Export a deterministic Mermaid or DOT projection of the territory graph for PRs and docs, optionally labeled with each node's active decision count so a reviewer sees where the recorded reasoning lives. Also provides the view-export entry used by the CLI `view` / `export` commands. Over MCP the diagram goes back as one result, and a host truncates a result over its size limit silently: a truncated Mermaid file is unusable and the agent does not learn that it was cut. So the MCP handler refuses a diagram over its character budget with the two fixes (`focus` for a neighborhood, `output` to write the whole diagram to a file the way the CLI does) instead of returning something the host would damage.

## Actor & Trigger

- **Actor:** coding agent via MCP (`if-mcp-tools`) or human/CI via CLI (`if-cli`)
- **Trigger:** `export_mindplan_view` tool or `mindplan-mcp view|export`

## Execution Logic

Package: `src/interactions/i-export-map/`

- Handler for `export_mindplan_view` (registered by `if-mcp-tools`)
- Export function callable by `if-cli` for `view` / `export` (format, focus, include_retired, output file)
- Projection substrate: `f-view-projection`
- Optional focus validation via `f-compiler-rules` `findNode`
- `decisions` (boolean, default false) is passed to the projection, which then labels each node with its active decision count; `runViewExport` accepts it too
- Automatic `mindplan/map.md` refresh after mutations is owned by `i-steer-plan` (calls `f-view-projection` directly)
- **`output`.** The MCP handler takes `output` (repo-relative path, resolved under the project root; a path outside the root or under `mindplan/` is Blocked) and then reuses `runViewExport`'s file write: the result is `{ format, node_count, edge_count, written_to }` with no `diagram`
- **Size budget.** `EXPORT_RESULT_BUDGET` = 80,000 characters, exported from this package (under Claude Code's 25,000-token result limit and claude.ai's 150,000 characters). Without `output`, a diagram longer than the budget is not returned: the handler throws `Blocked: the diagram is <n> characters, over the <budget> MCP result budget. Pass focus for one node's neighborhood, or output to write it to a file.` The CLI path never applies the budget (stdout and files have no such limit)

Depends on: `f-territory-store`, `f-view-projection`, `f-compiler-rules`. Belongs to: `j-territory-sdlc`.

**Tool definition.** `export_mindplan_view` is defined in this action's `tools.ts` (`defineTool`, `f-tool-kit`) and mounted by `if-mcp-tools`.

## Acceptance Criteria

- `export_mindplan_view` returns Mermaid and DOT (full or focused)
- CLI `view` / `export` produce the same diagram output as before
- Handler lives under this package; Interfaces only wire it
- `npm test` passes
- `export_mindplan_view({ decisions: true })` labels nodes with their active decision counts; without it the diagram is unchanged
- `export_mindplan_view({ output })` writes the diagram to that path and returns `written_to` and the counts with no `diagram`; a path outside the root or under `mindplan/` is Blocked
- A diagram over `EXPORT_RESULT_BUDGET` without `output` is an `isError` result whose text names the size, the budget, `focus`, and `output`; the same diagram with `output` is written in full; the CLI prints it in full
- A diagram within the budget is returned unchanged
