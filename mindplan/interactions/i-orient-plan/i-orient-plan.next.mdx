# Orient on the plan

## Purpose

Read-path orientation. `get_rules` returns only the mandatory project rules so each action can re-load them without the full playbook. A later session that skipped that call would treat rules as optional after the first `get_project`.

## Actor & Trigger

- **Actor:** coding agent or human via MCP (`if-mcp-tools`) or console API (`if-console-api`)
- **Trigger:** MCP/HTTP orient tools; `get_project` / `get_rules` with no arguments

## Execution Logic

Intended files: `src/interactions/i-orient-plan/`

- Keep existing query tools
- `get_project` — `{ path, description, rules, playbook }` (first read of dialect + brief)
- `get_rules` — `{ path, rules }` from `loadProjectBrief()`; empty string when the section is empty; no playbook, no description
- `orient_for_work` does **not** carry the brief

Depends on: `f-graph-search`, `f-territory-store`, `f-compiler-rules`, `f-source-index`.

## Acceptance Criteria

- `get_rules` returns the current rules string and path
- `get_project` still returns playbook + brief
- Verified via `npm test`
