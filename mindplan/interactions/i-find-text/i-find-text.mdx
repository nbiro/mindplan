# Find text in nodes

## Purpose

Lets an agent find the exact text of a node for an edit. Agents may also read the node files directly, but a plain grep does not say whether a line is unique in its slot. `patch_node_territory`'s `replace` edit needs a `find` string that occurs exactly once; `find_in_node` returns each match with a snippet that does, ready to paste. `search_graph` answers which nodes mention something.

## Actor & Trigger

- **Actor:** agent
- **Trigger:** the `find_in_node` and `search_graph` MCP tools (read; no orientation gate, no record or rules in the reply)

## PRD / Execution Logic

Intended files: `src/interactions/i-find-text/` (`handlers.ts`, `tools.ts`).

- **Searched text.** The text a `replace.find` is matched against: live is the body below the frontmatter without `## Rules` and `## Decisions` (the `body` `get_node_context` returns); an open revision is its revision file's body. Lines are read with `\n` endings; `replace` turns `\n` into the file's own line ending, so snippets work on CRLF files.
- `find_in_node({ node_id, text, slot?, change?, regex?, case_sensitive?, limit? })` → `{ node_id, text, matches: [{ slot, change?, line, section, match, snippet, occurrences, note? }], total, more?, hint? }`. Default: case-insensitive substring on one line; `regex` treats `text` as a JavaScript regular expression. Without `slot`, live plus the open revision `change` names or the only open one; with several and no `change`, live only with `hint`. `line` is 1-based, `section` the `## ` heading above it (or `null`), `match` the whole line, `snippet` the shortest run of whole lines around it (grown after, then before) that occurs exactly once in that slot. `limit` 1..100, default 20.
- `search_graph({ text, regex?, case_sensitive?, type?, limit? })` → `{ text, matches: [{ node_id, type, slot, change?, line, section, match }], total, more? }` over every node that is not cancelled or deprecated, live and each open revision, in id order; a `match` over 200 characters is cut around the match. `limit` 1..200, default 30.
- Blocked: unknown node, empty `text`, a multi-line `text` without `regex`, an invalid regex, `slot: "next"` with no open revision, the `change` errors of a node read.

## Acceptance Criteria

- A snippet passed as `replace.find` to `patch_node_territory` replaces exactly that occurrence, on LF and CRLF files and on an open revision
- A repeated line grows its snippet until it is unique
- `search_graph` lists matches across nodes and slots with `more` past `limit`
- Verified by `find-text.test.mjs`
