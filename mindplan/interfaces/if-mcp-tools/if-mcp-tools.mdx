# MCP tools

## Purpose

MCP stdio Interface that registers twenty-three tools. Each description leads with when to call the tool. Successful results attach a non-empty drift report via `withDrift` from `f-mcp-runtime`, except `get_project` and `get_rules`: `get_rules` runs before every action and would repeat the same report next to `orient_for_work`. Without the when-hints, a long session would treat tools as one-shot session-start helpers.

## Kind

MCP tool surface (stdio).

## Exposed Interactions

- `i-orient-plan` — read/orient tools including `get_project` and `get_rules`
- `i-steer-plan` — mutate tools including territory, project description, project rules, config, attachments
- `i-export-map` — `export_mindplan_view`

## Spec

Intended files: `src/interfaces/if-mcp-tools/`

- Register `get_rules`
- Lead every tool description with a when-clause
- On success, call `withDrift` from `f-mcp-runtime` (which uses `buildDriftReport` from `i-check-integrity`) so a non-empty report attaches as `drift` (`paths`, `unowned`, `reminder`)
- `get_project` and `get_rules` register without drift: their successful payload never carries `drift`. Every other tool keeps it.
- App Router / MCP mounts Interaction packages; Interface does not own core domain logic

Depends on: `f-mcp-runtime`, `f-domain-model`, `f-graph-search`, `f-view-projection`.

## Acceptance Criteria

- Twenty-three tools registered
- Every tool description starts with when to call it
- Non-empty drift attached on every successful tool except `get_project` and `get_rules`; clean tree omits `drift`
- `get_project` and `get_rules` omit `drift` even on a dirty tree
- Verified via `npm test`
