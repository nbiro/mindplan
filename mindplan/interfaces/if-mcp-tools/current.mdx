# MCP tools (set_implementation_files)

## Purpose

MCP stdio Interface that registers orient, steer, and export tools. Adds registration for `set_implementation_files`. Depends on Foundations used for Zod schemas.

## Kind

MCP tool surface (stdio).

## Exposed Interactions

- `i-orient-plan` — read/orient tools (including file queries)
- `i-steer-plan` — mutate tools including `set_implementation_files`
- `i-export-map` — `export_mindplan_view`

## Spec

Intended files: `src/interfaces/if-mcp-tools/`

- Register `set_implementation_files` with Zod schema (`node_id`, `files`, optional `slot`)
- Update schemas for `get_node_implementation` (`path` optional) and any role field on create
- Mount only; no domain logic
- Depends on `f-mcp-runtime`, `f-domain-model`, `f-graph-search`, `f-view-projection` for schemas/types already imported

## Acceptance Criteria

- New tool is registered and callable
- Existing tools keep names/envelopes
- No domain logic under this Interface
- Verified via `npm test`

## Atomic Ops

- [x] Register `set_implementation_files`
- [x] Update create / get_node_implementation schemas for role and path
- [x] Verified via MCP smoke

## Impact

The mount contract is unchanged: this Interface still only registers orient, steer, and export tools and still owns no domain logic. `update_node_status` now accepts an optional `revisions` array beside the single-node `node_id` / `new_status` form. The schema passes that array through to `i-steer-plan`. Tool names and the ok/guarded envelope stay the same.
