# Claude Code plugin

## Purpose

In Claude Code, the MindPlan duties agents skip most are still prose: read the brief before answering, re-read the rules after a context summary, and hand off only on a green check. This Interface makes Claude Code enforce them. It is a plugin, served from a marketplace in this repository, that registers the MCP server and wires three Claude Code hooks to the CLI: the existing write guard, the brief at session start and after compaction, and the check before a turn ends. It is one more channel for existing Interactions (`i-read-brief`, `i-check-integrity`). It owns no behavior: every decision runs in the project's own `mindplan-mcp`, so Cursor and other hosts keep the same server gates, and the playbook and `MINDPLAN.md` stay the way to reach them.

## Kind

Claude Code plugin and marketplace (configuration plus one launcher script; no code under `src/`).

## Exposed Interactions

- `i-read-brief`: the `SessionStart` hook (`mindplan-mcp hook session-start`)
- `i-check-integrity`: the `Stop` hook (`mindplan-mcp hook stop`)
- The `PreToolUse` write guard (`mindplan-mcp hook pre-tool-use`, `f-agent-hook`) is reached through `if-cli`, the same command `install_hook` writes into `.claude/settings.json`

## Spec

Intended files: `.claude-plugin/marketplace.json`, `plugin/`.

- **Marketplace.** `.claude-plugin/marketplace.json` at the repository root: marketplace `mindplan`, `owner`, one plugin entry `{ name: "mindplan", source: "./plugin" }`. Users add it with `/plugin marketplace add nbiro/mindplan` and install with `/plugin install mindplan@mindplan`; a team commits `extraKnownMarketplaces` and `enabledPlugins` (`"mindplan@mindplan": true`) to `.claude/settings.json`. The plugin directory is self-contained, because Claude Code copies only `plugin/` into its cache.
- **Manifest.** `plugin/.claude-plugin/plugin.json`: `name: "mindplan"`, `description`, `repository`, `license`, `homepage`. No `version` field: the plugin is config, its version is the commit, and behavior is versioned by the project's `mindplan-mcp`.
- **MCP server.** `plugin/.mcp.json` registers `mindplan` as exactly `npx mindplan-mcp`, the command the README tells projects to commit. Claude Code then treats a project registration of the same command as a duplicate and keeps the project's, and `npx` runs the project's locked copy. Without a project install, the server fails to start and `/mcp` shows it. Tools from a plugin-only registration are named `mcp__plugin_mindplan_mindplan__*`; nothing in MindPlan depends on the tool prefix.
- **Launcher.** `plugin/scripts/mindplan.mjs` (Node, no dependencies) runs every hook. It finds the project's installed package (`$CLAUDE_PROJECT_DIR/node_modules/mindplan-mcp/package.json`, else the hook payload's `cwd`), runs its `bin` with `process.execPath` and the given arguments, pipes stdin and stdout, and exits with the child's code. It exits 0 and prints nothing when no copy is installed, and when the installed version is below `MIN_HOOK_VERSION` (the first release with `hook session-start` and `hook stop`) for those two hooks. So a project without MindPlan, or with an older pin, sees no hook errors.
- **Hooks.** `plugin/hooks/hooks.json`, each command `node "${CLAUDE_PLUGIN_ROOT}/scripts/mindplan.mjs" hook <name>`:
  - `PreToolUse`, matcher `Edit|MultiEdit|Write|NotebookEdit` → `pre-tool-use`. A project that also has the `install_hook` entry gets two identical denies, which is harmless.
  - `SessionStart`, matcher `startup|clear|compact` → `session-start`
  - `Stop` → `stop`, `timeout` 60
- **Out of scope for this version** (add each as its own change once it proves needed): a `PostToolUse` coverage hint on source writes, a `PreToolUse` merge-gate check on `git commit` / `gh pr create`, skill stubs that call `get_skill`, a review subagent, slash commands, and the setup guide recommending the plugin over `install_hook`.

Depends on: nothing it imports. It runs `if-cli` subcommands as a process.

## Acceptance Criteria

- `claude plugin validate ./plugin` and validation of the marketplace pass
- Every hook command in `hooks.json` names a `hook` subcommand that `if-cli` answers
- The launcher with no installed `mindplan-mcp`, or one below `MIN_HOOK_VERSION`, exits 0 with no output; with one installed it passes stdin through and returns the CLI's stdout and exit code
- In a project with `mindplan-mcp` installed and the plugin enabled: a new session receives the brief, an `Edit` under `mindplan/` is denied, and a turn that leaves an unclaimed source file is sent back once with the `Blocked: Coverage` line
- Verified by `claude-plugin.test.mjs` (launcher and config shape) and one manual run in Claude Code
